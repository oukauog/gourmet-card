### 1. やること（データ層）

配置の方針：**画面に依存しない純粋なロジック**は `src/lib/`、**Dexie（IndexedDB）に触る層**は `src/db/`。どちらも React を import しない。

#### 1-1. 型定義 `src/db/types.ts`
仕様書 3.2〜3.6 に従う。要点：
- `Shop`：`id`（UUID、`crypto.randomUUID()`）、`name`（必須・trim 後に空なら登録不可）、`status`（`'visited' | 'wishlist'`）、`photoIds: string[]`（最大3、先頭が表紙。**並び順の正はこの配列**）、`rating?: number`（**1〜50 の整数**。3.7 なら 37。未評価は undefined）、`prefecture?`、`city?`、`stationId?`、`areaTagIds: string[]`、`genreTagIds: string[]`、`useTagIds: string[]`、`mapUrl?`、`memo?`、`origin`（`'self' | 'shared'`）、`createdAt`、`updatedAt`
- 日時は **ISO 8601 文字列（UTC、例 `2026-09-24T01:23:45.678Z`）**で持つ（書き出しファイルで人が読めるようにするため。工事8で JSON にそのまま出す）
- `Photo`：`id`、`shopId`、`small: Blob`（一覧用・長辺約400px）、`large: Blob`（店ページ用・長辺約1600〜2000px）、`width`/`height`（large の寸法）、`createdAt`。縮小処理そのものは工事2（ここでは Blob を受け取って保存するだけ）
- `Tag`：`id`、`kind`（`'area' | 'genre' | 'use'`）、`name`（表示名）、`normalizedKey`（1-2 の正規化キー）、`createdAt`
- `Setting`：`key`（文字列）、`value`。当面のキー：`lastBackupAt`（ISO 文字列）、`sortOrder`（`'newest' | 'rating' | 'name'`）、`columns`（2 | 3）。キー名と値の型は `SettingsMap` 型で列挙し、型安全に get/set できるようにする
- 県・市・駅はこの工事では**単なる文字列/ID**として扱う（選択式 UI・駅マスタは工事5・7）

#### 1-2. 純粋ロジック `src/lib/`
- `tagKey.ts`：`normalizeTagKey(name: string): string` — 全角/半角の同一視（`String.prototype.normalize('NFKC')`）、大文字/小文字の同一視（小文字化）、前後の空白除去、連続する空白は1つに。**ひらがな/カタカナや長音の違いは同一視しない**（仕様書 3.4 の範囲を超えない。必要になれば整理画面の統合で対応）
- `rating.ts`：
  - `isValidRating(n)`：1〜50 の整数のみ true
  - `ratingToText(37) → "3.7"`（小数1桁固定。`ratingToText(50) → "5.0"`、`ratingToText(undefined) → "未評価"`）
  - `ratingFromNumber(3.7) → 37`（浮動小数の誤差を丸めで吸収。`3.7 * 10` が `37.00000000000001` になっても 37）
  - `starFills(rating) → [1, 1, 1, 0.7, 0]` のような長さ5の配列（各☆の塗り割合 0〜1。仕様書 4.4。未評価は `[0,0,0,0,0]` を返し、表示側で「未評価」と区別するのは画面側の責務）
- `time.ts`：`nowIso()`（テストで差し替えられるよう、注入可能な形にしてよい）

#### 1-3. Dexie データベース `src/db/db.ts`
- クラス `GourmetDB extends Dexie`、DB名 `gourmet-card`、**`version(1)`**。テーブル：`shops` / `photos` / `tags` / `settings`
- インデックスの目安：`shops: id, status, createdAt, updatedAt, rating, prefecture, city, stationId, *genreTagIds, *areaTagIds, *useTagIds`／`photos: id, shopId`／`tags: id, kind, &[kind+normalizedKey]`（同じ種別で同じ正規化キーは1つだけ）／`settings: key`
- 単一インスタンスを export する。テストで DB 名を差し替えられるよう、ファクトリ関数（`createDb(name?)`）も用意する
- **スキーマ変更は今後 version を上げて upgrade を書く**旨をコメントで明記（工事2以降の実装役への注意）

#### 1-4. リポジトリ（操作）`src/db/`
`shops.ts` / `photos.ts` / `tags.ts` / `settings.ts` に分ける。複数テーブルにまたがる更新は必ず `db.transaction('rw', …)` で一括にする。

- **店**：`createShop(input)`（name 必須・trim・空なら例外。`status` 既定 `visited`、`origin` 既定 `self`、配列は空配列で初期化、`createdAt`/`updatedAt` 自動）／`getShop(id)`／`updateShop(id, patch)`（`updatedAt` 自動更新。`id`・`createdAt` は変更不可。`rating` は `isValidRating` で検証し不正なら例外。`name` を空にする更新は例外）／`deleteShop(id)`（その店の写真も同一トランザクションで削除）／`listShops({ status?, sort? })`（既定：`status` 指定なしで全件、`sort` 既定 `newest` = `createdAt` 降順。`rating` は高い順・未評価は末尾、`name` はロケール `ja` で昇順）／`countShops(status?)`
- **写真**：`addPhoto(shopId, { small, large, width, height })`（既に3枚なら例外。`photos` への追加と `shop.photoIds` への末尾追加を同一トランザクションで）／`removePhoto(photoId)`（`photoIds` からも外す）／`reorderPhotos(shopId, orderedIds)`（同じ集合の並べ替えでなければ例外。先頭＝表紙）／`getPhoto(id)`／`getPhotosForShop(shopId)`（`photoIds` の順で返す）
- **タグ**：`findOrCreateTag(kind, name)`（`normalizeTagKey` で既存を探し、あれば既存を返す。`name` の表示名は**最初に登録した表記を維持**）／`suggestTags(kind, partial)`（正規化キーの前方一致で候補を返す。入力補完用）／`renameTag(id, newName)`（正規化キーが同種別の別タグと衝突する場合は例外。統合は `mergeTags` を使わせる）／`mergeTags(fromId, toId)`（同種別のみ。`from` が付いている全店を `to` に付け替え（重複しない）、`from` を削除。全て同一トランザクション）／`deleteTag(id)`（付いている全店から外してから削除）／`listTags(kind?)`／`attachTag(shopId, tagId)` `detachTag(shopId, tagId)`（種別に応じた配列へ。重複は付けない）
- **設定**：`getSetting(key)` / `setSetting(key, value)`（`SettingsMap` に基づく型付き）

#### 1-5. テスト基盤の追加と単体テスト
- `fake-indexeddb` を devDependencies に追加。`vitest.config.ts` の `setupFiles` で `fake-indexeddb/auto` を読み込む（Dexie の import より前に効くこと）
- 各テストは独立した DB 名（またはテストごとに `db.delete()`）で始め、テスト間で状態を持ち越さない
- **Blob の保存確認**：`Photo.small / large` に `Blob` を入れて保存→読み戻し→中身（バイト列）が一致することをテストする。fake-indexeddb（Node）で Blob が扱えない場合は、**保存形式を `ArrayBuffer` に変えるのではなく**、まず Node 側の対処（`structuredClone` 対応版への更新等）を試し、それでも無理なら理由と代替案を報告書に書いて相談役の判断を待つ（実機の Safari では Blob 保存が本命のため）
- テストの必須項目（`src/lib/*.test.ts`、`src/db/*.test.ts`）：
  - `normalizeTagKey`：全角英数字↔半角、半角カナ↔全角カナ、大文字↔小文字、前後・連続空白、日本語（ひらがな/カタカナは別扱いのまま）
  - `rating`：1〜50 の**全値**で `ratingToText` ↔ `ratingFromNumber` が往復一致、0・51・小数・NaN は不正、`starFills` の代表値（37 → `[1,1,1,0.7,0]`、50 → 全1、1 → `[0.1,0,0,0,0]`）
  - 店：名前必須（空・空白のみで例外）、既定値、`updatedAt` の更新、`createdAt` 不変、削除で写真が消える、`listShops` の各ソート（未評価末尾を含む）
  - 写真：3枚制限、追加時に `photoIds` 末尾へ、`removePhoto` で配列から消える、`reorderPhotos` の不正入力で例外、表紙が先頭
  - タグ：`findOrCreateTag` が表記ゆれで同じタグを返す、`&[kind+normalizedKey]` の一意性、`renameTag` の衝突例外、`mergeTags` 後に店の参照が付け替わり重複せず `from` が消える、`deleteTag` で店から外れる、別種別なら同名でも別タグ
  - 設定：型付き get/set と未設定時の undefined
- 既存の `src/lib/sample.test.ts` は、実テストが揃ったら削除してよい（報告書に書く）
