## 1. 目的

自分が行った良い飲食店を「切れるカード（手札）」として貯め、聞かれたらその場でさっと見せる。友人に「富山でうまい所ない？」と聞かれた時、5秒で答えられることが最重要の評価軸。

裏の目的：お気に入り店の料理写真がずらっと並ぶコレクションとして、眺めて楽しめること。**見た目の華やかさは機能と同格の要件**。

### 1.1 作らないもの（スコープ外）
- 常時同期・フォロー等のSNS機能
- アカウント・ログイン
- サーバー上へのデータ保存（店データ・写真は各自の端末内のみ）
- 訪問日・訪問回数の記録
- 予算感の記録

### 1.2 後回し（将来の拡張候補。今は作らないがデータ形式で邪魔しない）
- GoogleマップURLからの店名・県・市の自動入力（短縮URL展開に小サーバーが要るため）
- コード発行によるお裾分け（方式2、小サーバー）
- メモの秘匿配慮（見せる時の折りたたみ、送信時の除外）

  - 見本データのボタン（DEV 限定）は公開版に出ない
  - どの版が出ているか分かるよう、登録・編集フォームの最下部（出典表記の下）に版（コミットの短いハッシュ＋ビルド日）を小さく出す。GitHub Pages の `index.html` はブラウザに10分ほどキャッシュされるため、公開直後は古い版が出ることがある
- 個人情報・APIキー等をリポジトリに入れないこと（現状そのようなものは無い）
- コミット作者メールは GitHub の noreply アドレスを使う（工事0の4コミットも書き換える。2026-09-24 決定）

### 2.3 端末内保存の性質（利用者に周知する事項）
- 写真は登録時にアプリ内へ**コピー**する。カメラロールから消してもアプリ側は消えない
- 次の場合はアプリ内データが消える：アプリをホーム画面から削除／Safariの「Webサイトデータを消去」／機種変更
- 対策：起動時に `navigator.storage.persist()` を要求（WebKitはホーム画面アプリだと許可しやすい方針）＋ **全店書き出し（バックアップ）を必須機能**とし、最終バックアップから一定日数で促す

## 3. データ設計

### 3.1 大原則
**必須は店名だけ。他はすべて任意。** 全部入れないと登録できない作りは不可（入力の手間が際限なく増えて使われなくなるため）。

### 3.2 店（Shop）
| 項目 | 型・内容 | 必須 | 備考 |
|---|---|---|---|
| id | 一意ID（UUID） | 自動 | お裾分け時の重複判定にも使う |
| name | 店名（文字列） | **必須** | |
| status | `visited`（手札）／`wishlist`（行きたい） | 自動 | 自分登録の初期値は visited、登録時に切替可 |
| photos | 写真ID配列（最大3、先頭が表紙） | 任意 | 並べ替えで表紙を変更可 |
| rating | 0.1〜5.0（0.1刻み）または未設定 | 任意 | 内部は整数（1〜50）で持つと誤差が出ない |
| prefecture | 都道府県（選択式） | 任意 | |
| city | 市区町村名（選択式。政令市は市まで） | 任意 | 県選択後に候補表示。県と組で意味を持つ（3.5） |
| stationId | 駅ID（駅データ.jp の駅グループコード。補足駅は x01〜） | 任意 | 駅マスタ参照（3.5） |
| areaTags | エリアタグID配列 | 任意 | 自由追加（例：総曲輪、八尾、国道8号沿い） |
| genreTags | ジャンルタグID配列 | 任意 | 自由追加（例：ラーメン、海鮮） |
| useTags | 使い道タグID配列 | 任意 | 用意リストから選択（例：個室あり） |
| mapUrl | GoogleマップURL | 任意 | タップで開くだけ。解析はしない |
| memo | 文字列 | 任意 | 常に表示・送信 |
| origin | `self`／`shared` | 自動 | お裾分けで取り込んだ店は shared |
| createdAt / updatedAt | 日時 | 自動 | 並び順（登録順）に使う |

### 3.3 写真（Photo）
- 1枚につき2サイズを保存（定数は `src/lib/imageSizes.ts`）
  - 一覧用（小）：長辺 **600px**、JPEG 品質 0.80（**工事3a で 400px → 600px に変更**。理由は下記）
  - 店ページ用（大）：長辺 **1800px**、JPEG 品質 0.85（2026-09-24 花井さん決定。1600〜2000 の中間）
  - 元画像が目標より小さければ拡大しない。透過 PNG は白背景で JPEG 化
- 元画像は保存しない（元の高画質はカメラロールに残る前提）
- **小サイズの根拠（工事3で判明）**：一覧のタイルは正方形に切り抜く（`object-fit: cover`）ため、効くのは小画像の**短辺**。iPhone の 4:3 写真は長辺 400px だと短辺 300px しかなく、3列（必要 386px）でも不足していた。長辺 600px（短辺 450px）にすると 3列は十分、2列（必要 582px）は約 77%。花井さんは 400px の 2列でも「甘さは気にならない」と判定しており、容量とのバランスで 600px に決定（2026-09-25）。**登録済みの写真の小画像は作り直さない**（試し登録のデータのみのため）
- 撮影向き（EXIF）・HEIC：**iPhone 実機で確認済み（2026-09-24）**。その場撮影・HEIC 横撮り・HEIC 縦撮りいずれも正しい向きで取り込めた。実装方針は 3.8 参照

### 3.4 タグ（Tag）
- 種別：`area`／`genre`／`use`
- 表記ゆれ対策（genre・area）
  1. 入力中に既存タグを候補表示（新規作成より選ぶ方が楽な画面にする）
  2. 全角/半角・大文字/小文字の違いは同一とみなす（正規化キーで一致判定）
  3. タグ整理画面：名前変更・統合（統合すると付いていた店は新しい方へ付け替え）
- use タグは初期リストを同梱：**「個室あり」「駐車場あり」の2つ**（2026-09-26 花井さん決定。「デート向き」「家族・子連れ」等は個人の主観でしかなく、自分が使う分には不要という理由で入れない）。後から追加・編集可
  - 初期リストは**初回起動時に一度だけ**作る（設定 `useTagsSeededAt` で記録。消した初期タグが次の起動で復活しないように）

### 3.5 駅マスタ・市区町村マスタ（工事7。2026-09-27 決定）
- 全国の駅と市区町村の一覧をアプリに同梱する（オフラインで候補表示できるように）。サーバーからは取らない
- **出典と利用条件（相談役が確認済み 2026-09-27）**

| 対象 | 出典 | 利用条件 | 出典表記 |
|---|---|---|---|
| 駅 | 駅データ.jp（https://ekidata.jp/）無料版の駅データ CSV | 商用・非商用とも可。加工の有無にかかわらず第三者に提供可（加工しない提供は無償に限る）→公開リポジトリに原データを置いてよい | 義務なし（規約で明記・リンクを歓迎）→表記する |
| 市区町村 | 総務省「全国地方公共団体コード」の Excel（令和6年1月1日更新。https://www.soumu.go.jp/denshijiti/code.html） | 公共データ利用規約（第1.0版）＝CC BY 4.0 互換 | **必須**。加工するので「〜を加工して作成」と書く |

- 駅データ.jp は無料会員登録でダウンロードする（花井さんが取得し、リポジトリの `data-src/ekidata/` に置く）。無料版には**駅名のカナ・ローマ字と、新幹線だけの駅が無い**
  - カナが無いので、駅の候補は**漢字（表記）で探す**。ひらがなでは出ない（iPhone は変換して入力する前提）
  - 新幹線だけの駅（黒部宇奈月温泉など18駅）は相談役が作った**補足表**で足す（`data-src/extra-stations.csv`）。在来線と同じ名前の駅（富山・新高岡など）は無料版にある
- 不採用：国土数値情報（鉄道）。登録不要で新幹線も入るが、年1回の更新で2026年の新駅が入らず、県・市が付いていないので地図データとの突き合わせ計算が要り、工事が重い
- **市区町村の単位（花井さん決定）：市まで**。政令指定都市は「大阪市」「札幌市」（区に分けない）。東京23区は「千代田区」など区ごと。郡は付けない（「上市町」）。件数は 1,741（1,718市町村＋23特別区、令和6年1月1日現在）の見込み
- 店に持つ値：`city` は市区町村名の文字列（県と組で意味を持つ。「府中市」は東京都と広島県にある）。`stationId` は駅データ.jp の**駅グループコード**（`station_g_cd`。同じ駅の複数路線をまとめる番号）の文字列。補足表の駅は `x01`〜
- 駅は運用中（`e_status=0`）だけを入れ、駅グループコードでまとめて1駅1件にする。所在地の市は住所から決める（決まらない駅は市なしで持ち、実装役が一覧を報告）
- **表示名**：駅名＋「駅」（「富山駅」。名前が「駅」「ステーション」で終わる時は付けない）。候補やパネルでは、同じ名前の駅が別の県にもある時だけ「府中駅（東京都）」と県を添える（同じ県に同名がある時は市を添える）
- 候補の順：前方一致 → 部分一致。それぞれの中で、選択中の県の駅を先に
- **駅から県・市の自動補完**：駅を選んだ時、県が空なら駅の県を、市が空で県が駅の県と同じなら駅の市を入れる。**入っている値は上書きしない**
- マスタは生成スクリプト（`npm run geo-data`）で原データから JSON を作り、リポジトリに入れる。アプリは**必要になった時に別ファイルとして読み込む**（一覧の最初の表示を重くしない）。原データが更新されたら、花井さんが CSV を差し替えて実装役に再生成を頼む
- 出典表記は登録・編集フォームの最下部に小さく出す（アプリの説明画面を作るなら工事10で移すか判断）
- **工事7の生成結果（2026-09-27 検収）**：市区町村 1,741件（Excel は 1,747件。北方領土の6村を団体コードで固定して除外。北海道の「泊村」重複も避けるため）。駅 8,783件（CSV 10,962行 → 運用中 10,465 → グループでまとめて 8,766 → 補足17駅。奥津軽いまべつは無料版に既にあったので足さない）。住所から市が決まらない駅 0件
  - グループの名前は代表の駅（駅コード＝グループコードの行）から取る。`e_sort` の先頭だと「魚津」→「新魚津」、「金沢」→「北鉄金沢」になるため
  - 同じ県・同じ市の同名駅（吹田・尼崎など JR と私鉄）は候補で見分けられない（路線名が無料版に無い。どちらでも場所は同じなので許容）
  - ~~保留~~：グループにまとめられた代表以外の名前（「梅田」→大阪、「電鉄富山」→富山 など約200件）は検索に出ない。いったん工事10へ回したが、花井さんが「東京の淡路町・小川町が出ない」と気づき「割と致命的」として**工事7aで先に直す**（2026-09-27。3.5.1）

#### 3.5.1 工事7a：グループの中の別の名前を独立した駅にする（2026-09-27 相談役判断）
- 分かったこと：駅データ.jp の駅グループは「同じ駅の複数路線」だけでなく**乗り換えできる近くの駅**もまとめる（御茶ノ水のグループ＝御茶ノ水・淡路町・新御茶ノ水・小川町（都営）。梅田は大阪のグループ）。代表以外の名前は約200件（東京38・大阪37・愛知14・京都13…、富山は宇奈月・新魚津・南富山駅前・電鉄富山）
- **直し方：代表と違う名前は、その名前で独立した1駅として足す**（別名で検索して代表の駅を選ぶ案は不採用。「淡路町」を選んだのに店ページに「御茶ノ水駅」と出ると分かりにくく、絞り込みも別の駅として扱う方が実際に合うため）
  - 「違う名前」の判定：NFKC・空白の除去・「ヶ」→「ケ」・括弧の種類をそろえる（〈〉と（）を同じに）・末尾の「駅」を外す、をした上で代表と違うもの。「押上（スカイツリー前）」「富山駅」（市内電車）「高岡駅」（万葉線）は代表に含めたまま
  - 足した駅の `stationId` は、その名前の行のうち**最も小さい駅コード**（`station_cd`）。駅コードと駅グループコードは同じ番号の体系で重ならない（生成時に重複が無いことを確かめる）
  - 足した駅の県・市はその駅の住所から（3.5 と同じ最長一致）
  - **既存の駅は id・名前・県・市とも変えない**（登録済みの店の `stationId` がそのまま使える）。データの形も変えない
- 表示名の追加ルール：名前が「駅前」で終わる時も「駅」を付けない（都電の「王子駅前」、市内電車の「南富山駅前」）
  - マスタは別ファイル（駅 231.6 kB／gzip 75.4 kB、市区町村 22.4 kB／gzip 8.9 kB）。xlsx 読み取りは devDependency `read-excel-file`

### 3.7 データ層の実装決定（工事1 検収時 2026-09-24）
- 配置: 純粋ロジック `src/lib/`、Dexie 層 `src/db/`。どちらも React を import しない。**公開 API の一覧は `reports/工事01_報告.md` 4章**（工事2以降はこれを見て使う）
- 評価の内部表現は **1〜50 の整数**（3.7 → 37）。`ratingFromNumber` は 0.1 刻みでない値（3.75 等）を**例外**にする（丸めない。画面側が 0.1 刻みで渡す）
- 日時は **ISO 8601 文字列（UTC、`toISOString()` 形式）**。工事8の取り込みでは他形式を同形式に正規化してから保存する
- 写真の並び順・表紙の正は `shop.photoIds` 配列。`photoIds` は写真 API（addPhoto / removePhoto / reorderPhotos）でのみ変更
- タグは `&[kind+normalizedKey]` で種別ごとに一意。正規化は NFKC＋小文字化＋空白整理のみ（ひらがな/カタカナ・長音は区別）。表示名は最初に登録した表記

### 3.8 画像処理と画面の実装決定（工事2 検収時 2026-09-24）
- 画像のデコードは `<img>`＋object URL が主経路（失敗時のみ `createImageBitmap`）。**EXIF の向きはブラウザのデコードに任せ、自前で回転しない**（二重回転の事故防止。iPhone 実機で正しい向きを確認済み）
- 縮小の canvas は目標サイズ（≤1800px）で作る（元画像サイズの canvas は iPhone の面積上限に当たる）。大・小とも元画像から直接作る。写真は1枚ずつ処理（メモリ対策）
- 写真の失敗は `ImageProcessError`（`userMessage`＝「この写真は読み込めませんでした」）。DOMException と同名のエラー名は引き続き禁止
- 店＋写真の保存は `src/db/createShopWithPhotos.ts`（公開 API のみで組んだ1トランザクション）。**Dexie の親トランザクションは子 API が触る全テーブル（shops・photos・tags）を含める**こと（欠けると `SubTransactionError`）
- ID 生成 `newId()` は `crypto.randomUUID` が無い環境（LAN の http）で `getRandomValues` による UUID v4 にフォールバック（`src/lib/id.ts`）
- 画面切替は工事2では `App.tsx` の `useState`。**工事3で自作ハッシュルーターに置き換え済み**（3.9 参照）
- 写真の選択は `<input type="file" accept="image/*" multiple>` を隠して `click()`（`capture` 属性なし）。iPhone で「写真を撮る／フォトライブラリ／ファイルを選択」が出ることを確認済み

- 配置：画面 `src/screens/`、部品 `src/components/`（PhotoPicker・BlobImage・Toast）、フック `src/hooks/`、スタイル `src/styles/app.css`

- **項目の並び（花井さん決定）**：写真 → 店名 → 手札/行きたい → 評価 → ジャンル → 使い道 → **最寄り駅 → 県 → 市** → エリア → GoogleマップURL → メモ（→ 出典表記）。駅を先に選ぶと県・市が自動で埋まり、入力が最も少ない

- 県を選んでいる時は、市・駅の候補をその県のものに絞る（選択中のものは残す）。チップ「場所」の数え方は 県 → 市 → 駅 → エリア の順で合わせる

  - **判定（2026-09-26 花井さん、iPhone 実機）：上部は「重ね」、比率は「4:5」**（比率は「迷うが 4:5」）。iPhone の戻るスワイプと写真の横スワイプの衝突なし、実機確認の手順はすべて問題なし。工事4a で 1:1・バーを撤去して固定
- 写真スワイプは**ライブラリなし**（CSS の scroll-snap）。2枚以上のときだけ位置を示す点を出す。写真は枠いっぱいに切り抜き（`object-fit: cover`）。店ページは `large` を使う
- **写真タップの全画面拡大（ピンチ）は作らない**。要否は工事10で判断
- 「編集」（工事5）・「この店を送る」（工事8）は**作る工事まで出さない**（押しても何も起きないボタンは置かない）。削除はページ最下部に控えめに残す
- 空の項目は見出しごと出さない（未評価だけは「未評価」と出す）。最寄り駅の表示は駅マスタと一緒に工事7
- Googleマップのボタンは `http:`/`https:` の URL のときだけ出し、別タブで開く（`javascript:` 等は出さない）。メモは改行を保って表示し、URL の自動リンクはしない

### 4.4 ☆表示ルール
- ☆5個。評価値をそのまま塗り量にする（3.7 → ☆3個全塗り＋4個目を70%塗り）

### 4.5 お裾分け・バックアップ画面
- 書き出し：1店（店ページから）／複数選択（一覧で選択モード）／全店（バックアップ）
- 共有：Web Share API でファイルを共有メニューに渡す（LINE・AirDrop・メール等）。非対応環境ではダウンロード
- 取り込み：「取り込む」→ファイル選択
  - 他人から来た店は origin=shared、status=wishlist で取り込む（自分のバックアップ復元時は元の状態のまま）
  - 同じidの店が既にある場合：スキップ／上書きを選択（初期はスキップ）
  - 相手のタグはそのまま取り込み（正規化キーが一致すれば既存タグに合流）。揺れは整理画面で統合
- バックアップの促し：最終書き出しから30日（仮）で一覧画面に控えめな案内
