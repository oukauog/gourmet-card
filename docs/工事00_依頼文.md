## 工事0：環境構築

あなたは「グルメカード」の実装役です。まず `CLAUDE.md` と `docs/01_仕様書.md` を読んでから着手してください。今回の工事は**環境構築のみ**です。アプリの機能（画面・データ層）は一切作らないでください。

### 環境の注意（日本語Windows）
- バッチファイル（.bat / .cmd）は作らない・使わない。スクリプトは npm scripts / Node / Python で書く
- コンソール出力は文字化けを避けるため英数字中心にする。ファイルは UTF-8（BOMなし）で読み書きする
- パスに日本語・空白が含まれる前提でクォートする

### やること

1. **Git 初期化**
   - `git init`、`.gitignore`（node_modules、dist、Playwright の出力、`.env` 等）
   - 既にある `CLAUDE.md` と `docs/01_仕様書.md` を最初のコミットに含める（`chore: initial docs`）
   - 以降の作業はブランチ `work/00-setup` で行い、動いた状態ごとにコミットする
   - GitHub の公開リポジトリ `gourmet-card` へ push できれば行う（`gh` CLI が使える場合のみ）。使えない場合は push せず、花井さんが手で行う手順を報告書に書く

2. **Vite ＋ TypeScript ＋ React の雛形**
   - `npm create vite@latest` 相当で作成（テンプレート react-ts）。プロジェクト直下に生成すること（サブフォルダを作らない）
   - `vite.config.ts` に、スマホから同一LANで見るための `server.host: true` を設定
   - `index.html` の `<title>` を「グルメカード」、`lang="ja"`、viewport は `width=device-width, initial-scale=1, viewport-fit=cover`
   - 初期画面は「グルメカード（準備中）」と1行表示するだけの空画面でよい

3. **依存の導入（インストールと最小の動作確認のみ。使い込まない）**
   - `dexie`、`jszip`、`vite-plugin-pwa`（設定はまだ有効化しない。インストールのみ）
   - `vitest`、`@playwright/test`（Chromium のみインストール）
   - 各ライブラリのバージョンを報告書に記載

4. **テスト基盤**
   - Vitest：`src/lib/sample.test.ts` に「1+1=2」程度のサンプルテスト1本。`npm test` で走る
   - Playwright：`e2e/smoke.spec.ts` に、スマホ幅（390×844）で開いて「グルメカード」の文字が表示されることを確認するテスト1本。`npm run e2e` で走る（dev サーバー自動起動の設定込み）
   - `npm run typecheck`（tsc --noEmit）、`npm run build` も通ること

5. **npm scripts の整備**
   - `dev` / `build` / `preview` / `test` / `e2e` / `typecheck` / `lint`（ESLint はテンプレート同梱のもので可）

6. **フォルダ**
   - `reports/` と `docs/` を用意（`docs/01_仕様書.md` は既にある。編集しない）

7. **技術スタックの最終確認（仕様書 2.1）**
   - 仕様書 2.1 の構成で問題ないか、実装役の視点で異論があれば報告書に書く（変更はしない）

### やらないこと
- アプリの画面・データ層・PWA有効化・GitHub Pages への公開
- `docs/01_仕様書.md` と `CLAUDE.md` の編集

### 完了条件
- `npm run typecheck` / `npm test` / `npm run e2e` / `npm run build` がすべて通る
- `npm run dev` で PC ブラウザに空画面が表示され、コンソールに表示された LAN 側の URL（`http://192.168.x.x:5173` の形）がある
- `git status` がクリーンで、`work/00-setup` にコミット済み
