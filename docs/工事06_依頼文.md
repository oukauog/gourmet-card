### 1. やること

#### 1-1. 絞り込み・件数の純粋関数（`src/lib/` の新規ファイル。例 `shopFilter.ts`）
- 条件の型（例）：`{ prefectures: string[]; areaTagIds: string[]; genreTagIds: string[]; useTagIds: string[]; minRating?: number /* 30|35|40|45 */; unratedOnly: boolean }`。空の条件を作る関数・「何か効いているか」を返す関数も用意
- 判定ルール（仕様書 4.1.1）：
  - 県：選んだ県の**どれか**に一致（県が未設定の店は、県を選んでいる時は出ない）
  - エリア・ジャンル：選んだタグの**どれか**が付いている
  - 使い道：選んだタグが**全部**付いている
  - 評価：`rating >= minRating`（整数 1〜50 で比較。未評価の店は出ない）
  - 未評価のみ：`rating` が未設定の店だけ
  - 種類をまたぐと「かつ」。空の条件は全件
  - 評価と未評価のみは**同時に効かない**：片方を入れる関数がもう片方を解除する（例 `setMinRating` は `unratedOnly=false` に、`setUnratedOnly(true)` は `minRating` を外す）
  - もう存在しないタグ ID・どの店にも無い県が条件に入っていても例外にしない（その条件に当てはまる店が無いだけ）
- 候補と件数（パネル用）：「今のタブの店」（他の条件は無視）で、県・エリア・ジャンル・使い道ごとに、1件以上の店に付いているものと件数を返す。並びは**件数の多い順、同数は名前順**（`Intl.Collator('ja')`）。選択中のものは 0件でも候補に残す（外せるように）
- チップの表示文字を作る関数：未選択は種類名（「場所」「ジャンル」「使い道」「評価」）、1つなら名前（「ラーメン」「富山県」）、2つ以上は「最初の名前 ほかN」（場所は県とエリアを合わせて数える）、評価は「4.0以上」
- 全部 Vitest で恒久テスト（上の各ルール・どれか/全部/かつの組み合わせ・排他・候補の並びと件数・0件の選択中が残ること・壊れた ID）

#### 1-2. 一覧画面の構成（`HomeScreen` を改修。部品は新規ファイルで足す）
上から次の順（上部は**固定しない**。スクロールで一緒に流れる）：
1. 上部バー（今のまま：題名「グルメカード」・列数ボタン）
2. **タブ**「手札」「行きたい」：セグメント型。件数つき（例「手札 12」「行きたい 3」。件数は条件をかける前のそのタブの全件）。起動時は「手札」
3. **絞り込みチップ列**：横スクロール（折り返さない）。「場所」「ジャンル」「使い道」「評価」「未評価のみ」。
   - 条件が効いているチップは塗りつぶし（濃い地に白文字など）で、1-1 の表示文字を出す。パネルを開くチップには小さな「▾」
   - 「未評価のみ」はパネルを開かず、タップでオン/オフ
   - 列の左右は 16px 空け、iPhone の画面左端（戻るスワイプの場所）から始まらないようにする
4. **件数と並び順の行**：左に件数（条件なし「12件」／絞り込み中「3件（12件中）」＋小さな「条件を解除」）。右に並び順「新しい順 ▾」（タップでパネル）
5. タイル一覧（見た目・列数・スクロール位置の復元は今のまま）
- 空の時の表示：
  - 手札が0件（条件なし）：今の「＋から最初のお店を登録」
  - 行きたいが0件（条件なし）：「行きたいお店はまだありません」
  - 条件で0件：「条件に合うお店がありません」＋「条件を解除」ボタン
- DEV 限定の見本バーは今までどおり出す（置き場所は邪魔にならない所でよい）
- 部品の置き場所・分け方は任せる（例 `src/components/filter/`、スタイルは新規 `src/styles/filter.css`）。`ShopTile`・タイルの見た目・`home.css` の既存ルールは変えない（新しい部品用のルールは新規 CSS に）

#### 1-3. 下から出る選択パネル（新規部品）
- 画面下から出るパネル（高さは内容に合わせ、最大で画面の 70% 程度・中はスクロール）。背景は半透明の黒で、背景タップで閉じる。PC では Esc でも閉じる。`role="dialog"`・`aria-modal`・見出し付き
- パネルの中：見出し（例「ジャンル」）＋その種類だけの「クリア」、候補のチップ（件数つき「ラーメン 5」、選択中は塗りつぶし、タップで付け外し）、下部に「N件を表示」ボタン（押すと閉じる）。`env(safe-area-inset-bottom)` を考慮
- **選んだその場で一覧に反映**（「N件を表示」の N も連動）
- パネルの種類：
  - **場所**：「県」の段（候補チップ）と「エリア」の段（候補チップ）。候補が無い段は出さない。**市・最寄り駅は工事7で足す**ので、段を足しやすい作りにしておく
  - **ジャンル**・**使い道**：候補チップ
  - **評価**：1択「指定なし／3.0以上／3.5以上／4.0以上／4.5以上」
  - **並び順**：1択「新しい順／評価の高い順／名前順」（選ぶと閉じてよい）
- 候補が1つも無い時（例：ジャンルタグがまだ無い）は「まだありません」と出す
- パネルが開いている間、裏の一覧がスクロールしないようにする（iPhone で背景が動かないこと。方法は任せる）
- パネルは履歴に積まない（URL は `#/` のまま）

#### 1-4. 状態の持ち方
- 一覧のデータは**全店（両タブ）を一度読み**、タブ・絞り込み・件数はメモリ上で計算する（タブ切替・チップ操作で DB を読み直さない）。並び順は既存の `listShops({ sort })` の並びを使う（比較関数を新しく書き直さない。並び順を変えた時は読み直してよい）
- タグ名は `listTags()` で読む
- **並び順**：`settings.sortOrder` に保存し、起動時に読む（未設定なら `newest`）。評価の高い順は未評価が最後（既存の比較のまま）
- **タブと条件**：今の `lastRows`・`lastScrollY` と同じくモジュール変数に持つ。店ページ・編集・登録から戻った時は残り、**再読み込み・アプリを開き直すと「手札・条件なし」**。`settings` には保存しない
- タブと条件は両タブ共通（タブを切り替えても条件はそのまま）。**タブを切り替えたら一覧の先頭へスクロール**。条件・並び順を変えた時はスクロール位置を変えなくてよい（チップは一覧の上にあるので自然に先頭付近）
- 店ページから戻った時のスクロール位置の復元（工事3）はそのまま効くこと
- 「行った！」で手札になった店は、一覧に戻ると手札タブに出る（読み直しで反映）

#### 1-5. 見本データ（`src/dev/sampleData.ts`。DEV 限定）
- 「見本用に増やす」で、一部（例：5件に1件）を `status: 'wishlist'` で作るようにする（行きたいタブの確認用）。それ以外の中身・「見本データを消す」の動きは変えない。既存テストが通ること、wishlist が混ざることをテストで固定

#### 1-6. e2e（スマホ幅 390×844。新規 `e2e/filter.spec.ts`）
店の用意は既存 e2e のやり方に合わせてよい（UI で登録、または `page.evaluate` で公開 API を呼ぶ等）。最低限：
- タブ：初期は「手札」。手札と行きたいの店が分かれて出る、件数がタブに出る。「行きたい」の店で「行った！」→編集をキャンセル→一覧に戻ると手札タブに出る
- ジャンル2つ選ぶと「どれか」、使い道2つ選ぶと「両方付いた店だけ」、ジャンル＋県で「かつ」
- 評価「4.0以上」で 3.9 と未評価が消え 4.0 が残る。「未評価のみ」をオンにすると評価の条件が外れる（逆も）
- 候補：今のタブの店に付いているタグだけが件数つきで出る（どの店にも付いていないタグは出ない）。選択中のタグは、タブを変えて 0件になっても候補に残り外せる
- チップの表示：「ラーメン」→2つ目を選ぶと「ラーメン ほか1」。塗りつぶしになる
- 件数の行：「3件（12件中）」の形。条件で0件の時の表示と「条件を解除」で全件に戻る
- 並び順：3種で順番が変わる。**再読み込みしても並び順は残り、タブと条件は「手札・条件なし」に戻る**
- 条件をかけた状態で店ページを開いて戻る → タブ・条件・スクロール位置が残っている
- パネル：背景タップで閉じる、「N件を表示」の N が選択に合わせて変わる
- 既存の e2e は、**仕様変更に合わせた箇所だけ**直す（例：行きたいの店が初期表示に出なくなった、空の時の文言）。直した箇所は表にして報告。それ以外は全部そのまま通ること
