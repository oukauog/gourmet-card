## 4. 絞り込みの作り（`src/lib/shopFilter.ts`）

### 条件の型

```ts
interface ShopFilter {
  prefectures: string[]
  areaTagIds: string[]
  genreTagIds: string[]
  useTagIds: string[]
  minRating?: number // 30 | 35 | 40 | 45（整数 1〜50 で比較）
  unratedOnly: boolean
}
```

- `emptyFilter()`・`isFilterActive(f)` を用意した
- 判定が見るのは店の `prefecture`・`rating`・3種のタグ配列だけ（`FilterableShop` 型）

### 判定ルール（`matchesFilter`。種類の順に1つでも外れたら false ＝「かつ」）

| 種類 | 規則 |
|---|---|
| 県 | 選んだ県の**どれか**と一致。県が未設定の店は、県を選んでいる時は出ない |
| エリア・ジャンル | 選んだタグの**どれか**が付いている（`some`） |
| 使い道 | 選んだタグが**全部**付いている（`every`） |
| 評価 | `rating >= minRating`（整数どうし）。未評価の店は出ない |
| 未評価のみ | `rating` が未設定の店だけ |

- 空の条件は全件
- 並びは渡された順のまま返す（`listShops({ sort })` の並び）
- もう存在しないタグ ID や、どの店にも無い県が条件に入っていても、例外にはならない（当てはまる店が無いだけ）

### 排他
- `setMinRating(f, r)`: 評価を入れると `unratedOnly` を false にする。外す（`undefined`）時は `unratedOnly` はそのまま
- `setUnratedOnly(f, true)`: `minRating` を外す。false にする時は評価はそのまま
- 画面の操作は必ずこの2つを通るので、両方が同時に効くことは無い
- 仮に両方入った条件を渡された場合は、「未評価のみ」を優先する

### 候補と件数（`filterOptions(今のタブの店, 条件, タグ名)`）
- 条件自体は無視し、今のタブの店だけで数える
- 1件以上の店に付いている県・タグと、その件数を返す（同じ店で ID が重複していても1件と数える）
- 並びは件数の多い順、同数は `Intl.Collator('ja')` の名前順
- 選択中のものは0件でも残す（タブを変えても外せるように）
  - 選択中で名前が引けない（削除された）タグは「（削除されたタグ）」と表示
  - 店に付いていても名前が引けないタグ ID は、候補から外す

### チップの文字
- `filterChipLabels(f, タグ名)`
  - 未選択は種類名（場所・ジャンル・使い道・評価）
  - 1つなら名前
  - 2つ以上は「最初の名前 ほかN」
  - 場所は県 → エリアの順に合わせて数える
  - 評価は「4.0以上」
- 「最初の名前」は選んだ順の最初です（付け外しは選んだ順を保つ）
- 件数の文字は `resultCountText`

## 5. 状態の持ち方（`HomeScreen.tsx`）

- **読み込み**: 一覧を開いた時（と並び順を変えた時、見本データのボタンの後）に、次をまとめて1回だけ読む
  - `listShops({ sort })`（**全店・両タブ**）
  - `listTags()`
  - 各店の表紙の small
- **メモリ上で計算するもの**（DB は読み直さない）: タブの件数・今のタブの店・絞り込み結果・パネルの候補
  - 計算は `useMemo` で、データ・タブ・条件が変わった時だけ行う
  - 並びは `listShops` の並びをそのまま使い、比較関数は書いていない
  - 並び順を続けて変えても古い読み込み結果で上書きしないよう、最後に始めた読み込みだけを反映する
- **モジュール変数に持つもの**（工事3の `lastRows`・`lastScrollY` と同じ考え方。アプリが動いている間だけ残る）
  - 前回のデータ（全店とタグ名）・列数・並び順・スクロール位置
  - **タブと条件**（`lastTab`・`lastFilter`）
  - 店ページ・編集・登録から戻った時は、同じタブ・条件・スクロール位置で一覧をすぐ出し、裏で読み直す
- **並び順の保存**: 変えた時に `setSetting('sortOrder', …)`。起動時に `getSetting('sortOrder')`（未設定なら `newest`）
  - 評価の高い順は未評価が最後（既存の `listShops` の比較のまま）
- **再読み込み・開き直し**: モジュール変数が消えるので「手札・条件なし」に戻る（並び順と列数は設定から読む）。条件は URL にも settings にも保存していない
- **タブを切り替えた時**: 一覧の先頭（ページの一番上）へスクロールする。条件・並び順の変更ではスクロールしない
- 「行った！」で手札になった店は、一覧に戻った時の読み直しで手札タブに移る（e2e で確認）

## 6. パネルの作り（`BottomSheet.tsx`・`scrollLock.ts`・`FilterPanel.tsx`）

- 画面下から出るパネルです
  - 高さは中身に合わせ、最大 `70dvh`。中身だけがスクロールする（`overscroll-behavior: contain`）
  - 背景は黒 45%。下端は `env(safe-area-inset-bottom)` を考慮した
  - 出る時に 0.2 秒ほど下から上がる。動きを減らす設定の端末では動かない
- `role="dialog"`・`aria-modal="true"`・見出し（`aria-labelledby`）。開いた時にパネルへフォーカスを移す
- **閉じ方**: 背景タップ、Esc（PC）、「N件を表示」、並び順は選んだ時点で閉じる。**履歴には積まない**（URL と `history.length` が変わらないことを e2e で確認）
- **背景スクロールの止め方**
  - iOS Safari では `body { overflow: hidden }` だけでは、指のスクロールを止められません
  - そこで開いた時に、その時のスクロール位置で `body` を `position: fixed; top: -Y px` に固定し、閉じた時に元のスタイルへ戻して `scrollTo(0, Y)` で位置を戻しています
  - 固定中は `window.scrollY` が 0 になるため、一覧がスクロール位置を覚える時は `pageScrollY()`（固定中は固定前の値）を使う。パネルを開いたまま戻るスワイプで画面を離れても、位置を正しく覚えるため
- **パネルの中**
  - 見出し＋その種類だけの「クリア」（何も選んでいない時は押せない）
  - 候補のチップ（「ラーメン 5」。選択中は濃い地、タップで付け外し）
  - 候補が1つも無ければ「まだありません」
- **場所パネル**: 「県」と「エリア」の段を配列で持っています。候補が無い段は出しません
  - 工事7で市・駅の段を足す時は、`sectionsOf` の `place` に1行ずつ足せば済みます（判定は `shopFilter.ts` に条件を足す）
- **評価パネル**: 「指定なし／3.0以上／3.5以上／4.0以上／4.5以上」の1択（`role="radio"`）

### iPhone で気をつけた点
- チップ列は `body` の左右 16px の内側に収め、画面の左端（戻るスワイプの場所）から始まらないようにした。横スクロールの端でページやブラウザに動きが伝わらないよう、`overscroll-behavior-x: contain` を付けた
- タップの反応を良くするため、`-webkit-tap-highlight-color: transparent`・高さ 36〜40px のチップにした
- 上部（タブ・チップ）は固定していないので、下までスクロールした後に絞り込むには上へ戻る必要があります（仕様どおり）

## 11. 設計上の判断・迷った点

1. **表紙の読み込み**: 全店（両タブ）の表紙の small を最初に読みます。タブの切り替えで読み直さないためです。数百店までなら small は数十 KB ずつなので問題ない見込みです（工事3報告 8章3と同じ見立て）
2. **候補の件数は条件をかける前の数**: 仕様どおり「今のタブの店」で数えるので、例えば「富山県」で絞った後のジャンルのパネルでも、件数は手札全体での数です（`04-panel-genre.png` で「6件を表示」なのにジャンルの件数は 5・4…）
   - 「今の条件で何件に絞れるか」とは違う数なので、使ってみて分かりにくければ、工事10で「ほかの条件をかけた後の件数」に変える案があります
3. **「条件を解除」は2か所に出る**: 0件の時は、件数の行の小さな文字と、中央の大きなボタンの両方に出ます（どちらも同じ動き）
4. **「未評価のみ」はパネルを開かない**: 押すとその場でオン/オフし、オンの時は濃い地になります。評価の条件と排他なので、オンにすると評価チップは「評価」に戻ります
5. **タブを切り替えた時の先頭**: ページの一番上（`scrollTo(0, 0)`）に戻します。タブ・チップが上部にあるので、「一覧の先頭」と「ページの先頭」はほぼ同じ位置です
6. **見本バーの場所**: タイル一覧の下に移しました。見本データの e2e は、ボタンの名前で探すので影響ありません
7. **パネルのボタン名**: 候補は `aria-pressed` 付きのボタン、評価・並び順は `role="radio"` にしました。読み上げで「選択中」が分かるようにするためです
8. **「最初の名前 ほかN」の「最初」**: 選んだ順の最初です。候補の並び（件数順）ではありません

## 12. 花井さんの iPhone 実機確認手順

1. PC で `git pull` → `git switch work/06-filter` → `npm run dev` → iPhone の Safari で `Network:` の URL を開き、再読み込み
   - 店が少なければ、一覧の一番下の開発用バーで「見本データを消す」→「見本用に増やす」（行きたいの店・タグ・県が入った見本ができる）
2. **タブ**: 「手札」「行きたい」で店が分かれる、タブの件数が合っている
3. **絞り込み**
   - 県・ジャンル・使い道・評価・未評価のみを試し、思った店だけ残るか
   - チップに条件が出て一目で分かるか
   - 「条件を解除」で戻るか
4. **パネル**
   - 下から出る・閉じる（背景タップ・「N件を表示」）の操作が自然か
   - 開いている間に裏の一覧が動かないか
   - 候補の件数が合っているか
5. **並び順**: 3種を切り替え、Safari を完全に終了して開き直しても並び順は残り、タブは手札・条件は消えているか
6. **戻った時の状態**
   - 条件をかけて店ページを開き、画面左端からの戻るスワイプで戻る → 条件とスクロール位置が残っているか
   - チップ列を横にスクロールする時に、戻るスワイプとぶつからないか
7. **使い勝手**: 「富山のうまい所ない？」と聞かれた想定で、一覧から数タップ（例: 場所 → 富山県 → ジャンル → ラーメン → 評価 → 4.0以上）で見せられるか
