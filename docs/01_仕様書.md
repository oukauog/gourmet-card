## 1. 目的

自分が行った良い飲食店を「切れるカード（手札）」として貯め、聞かれたらその場でさっと見せる。友人に「富山でうまい所ない？」と聞かれた時、5秒で答えられることが最重要の評価軸。

裏の目的：お気に入り店の料理写真がずらっと並ぶコレクションとして、眺めて楽しめること。**見た目の華やかさは機能と同格の要件**。

### 1.1 作らないもの（スコープ外）
- 常時同期・フォロー等のSNS機能
- アカウント・ログイン
- サーバー上へのデータ保存（店データ・写真は各自の端末内のみ）
- 訪問日・訪問回数の記録
- 予算感の記録

### 1.2 後回し（将来の拡張候補。今は作らないがデータ形式で邪魔しない）
- GoogleマップURLからの店名・県・市の自動入力（短縮URL展開に小サーバーが要るため）
- コード発行によるお裾分け（方式2、小サーバー）
- メモの秘匿配慮（見せる時の折りたたみ、送信時の除外）

### 2.1 技術スタック（工事0で確定）

- IndexedDB ラッパー: Dexie.js 4
- PWA化: vite-plugin-pwa（工事9で有効化）
- 書き出しファイル: ZIP（JSON＋画像）。JSZip（重ければ工事8で fflate を検討）
- テスト: Vitest（ロジック。IndexedDB を使うテストは fake-indexeddb 6.2.5 を工事1で追加。Node 上で Blob 保存の往復も確認済み）、Playwright（スマホ幅 390×844、Chromium。WebKit 追加を工事2 or 8 で検討）
- Lint: oxlint（Vite テンプレート同梱。ESLint ではない）
- npm scripts: dev / build / preview / test / e2e / typecheck（`tsc -b --noEmit`）/ lint
- dev サーバー: port 5173 固定（strictPort）、`host: true` で LAN 公開。iPhone は `Network:` に出た URL で開く
- **LAN の http は secure context ではない**（工事2で判明）。`crypto.randomUUID`・`navigator.storage.persist`・Web Share API・Service Worker は使えないため、これらを使う工事（8・9）の実機確認は https が必要。開発サーバーの https 化（`@vitejs/plugin-basic-ssl` 等）か GitHub Pages 経由の確認かを**工事8の前に決める**（8章 確認事項6）。PC の e2e は localhost（secure context 扱い）のため、この差は検出できない
- 選定理由: 情報量が多く実装役が迷いにくい定番構成。静的ファイルだけで動くので無料ホスティングに載る

### 2.3 端末内保存の性質（利用者に周知する事項）
- 写真は登録時にアプリ内へ**コピー**する。カメラロールから消してもアプリ側は消えない
- 次の場合はアプリ内データが消える：アプリをホーム画面から削除／Safariの「Webサイトデータを消去」／機種変更
- 対策：起動時に `navigator.storage.persist()` を要求（WebKitはホーム画面アプリだと許可しやすい方針）＋ **全店書き出し（バックアップ）を必須機能**とし、最終バックアップから一定日数で促す

## 3. データ設計

### 3.1 大原則
**必須は店名だけ。他はすべて任意。** 全部入れないと登録できない作りは不可（入力の手間が際限なく増えて使われなくなるため）。

### 3.2 店（Shop）
| 項目 | 型・内容 | 必須 | 備考 |
|---|---|---|---|
| id | 一意ID（UUID） | 自動 | お裾分け時の重複判定にも使う |
| name | 店名（文字列） | **必須** | |
| status | `visited`（手札）／`wishlist`（行きたい） | 自動 | 自分登録の初期値は visited、登録時に切替可 |
| photos | 写真ID配列（最大3、先頭が表紙） | 任意 | 並べ替えで表紙を変更可 |
| rating | 0.1〜5.0（0.1刻み）または未設定 | 任意 | 内部は整数（1〜50）で持つと誤差が出ない |
| prefecture | 都道府県（選択式） | 任意 | |
| city | 市区町村（選択式） | 任意 | 県選択後に候補表示 |
| stationId | 駅ID | 任意 | 駅マスタ参照 |
| areaTags | エリアタグID配列 | 任意 | 自由追加（例：総曲輪、八尾、国道8号沿い） |
| genreTags | ジャンルタグID配列 | 任意 | 自由追加（例：ラーメン、海鮮） |
| useTags | 使い道タグID配列 | 任意 | 用意リストから選択（例：個室あり） |
| mapUrl | GoogleマップURL | 任意 | タップで開くだけ。解析はしない |
| memo | 文字列 | 任意 | 常に表示・送信 |
| origin | `self`／`shared` | 自動 | お裾分けで取り込んだ店は shared |
| createdAt / updatedAt | 日時 | 自動 | 並び順（登録順）に使う |

### 3.3 写真（Photo）
- 1枚につき2サイズを保存（定数は `src/lib/imageSizes.ts`）
  - 一覧用（小）：長辺 **600px**、JPEG 品質 0.80（**工事3a で 400px → 600px に変更**。理由は下記）
  - 店ページ用（大）：長辺 **1800px**、JPEG 品質 0.85（2026-09-24 花井さん決定。1600〜2000 の中間）
  - 元画像が目標より小さければ拡大しない。透過 PNG は白背景で JPEG 化
- 元画像は保存しない（元の高画質はカメラロールに残る前提）
- **小サイズの根拠（工事3で判明）**：一覧のタイルは正方形に切り抜く（`object-fit: cover`）ため、効くのは小画像の**短辺**。iPhone の 4:3 写真は長辺 400px だと短辺 300px しかなく、3列（必要 386px）でも不足していた。長辺 600px（短辺 450px）にすると 3列は十分、2列（必要 582px）は約 77%。花井さんは 400px の 2列でも「甘さは気にならない」と判定しており、容量とのバランスで 600px に決定（2026-09-25）。**登録済みの写真の小画像は作り直さない**（試し登録のデータのみのため）
- 撮影向き（EXIF）・HEIC：**iPhone 実機で確認済み（2026-09-24）**。その場撮影・HEIC 横撮り・HEIC 縦撮りいずれも正しい向きで取り込めた。実装方針は 3.8 参照

### 3.4 タグ（Tag）
- 種別：`area`／`genre`／`use`
- 表記ゆれ対策（genre・area）
  1. 入力中に既存タグを候補表示（新規作成より選ぶ方が楽な画面にする）
  2. 全角/半角・大文字/小文字の違いは同一とみなす（正規化キーで一致判定）
  3. タグ整理画面：名前変更・統合（統合すると付いていた店は新しい方へ付け替え）
- use タグは初期リストを同梱：**「個室あり」「駐車場あり」の2つ**（2026-09-26 花井さん決定。「デート向き」「家族・子連れ」等は個人の主観でしかなく、自分が使う分には不要という理由で入れない）。後から追加・編集可
  - 初期リストは**初回起動時に一度だけ**作る（設定 `useTagsSeededAt` で記録。消した初期タグが次の起動で復活しないように）

### 3.5 駅マスタ
- 全国の駅一覧をアプリに同梱（オフラインで候補表示できるように）
- 表示名：同名駅がある場合のみ「府中（東京都）」のように県名を併記
- 候補の優先：県が選択済みならその県の駅を優先
- **市区町村の選択も工事7で入れる**（2026-09-26 決定）。全国の市区町村一覧（約1,900件）の同梱が必要で、駅→県・市の自動補完にも同じデータが要るため、利用条件の確認とまとめて行う。工事5の入力は県（47択）だけ
- 駅選択時、県・市が空なら駅の所在地で自動補完（上書きはしない）
- データ候補：国土数値情報（鉄道）※2020年以降版はオープンデータ規約。駅名・路線・事業者を含むが県市は別途付与が要る見込み。代替：駅データ.jp 等。**工事7の前に利用条件と出典表記を相談役が確定**

### 3.6 設定（Settings）
- 最終バックアップ日時、並び順・列数などの表示設定
- キー: `lastBackupAt`（ISO文字列）／`sortOrder`（newest | rating | name。**未設定時の既定は newest**。工事6で一覧の並び順パネルから保存）／`columns`（2 | 3。**未設定時の既定は 3**。工事3で一覧の切替ボタンから保存済み）／`useTagsSeededAt`（ISO文字列。使い道タグの初期リストを作った日時。工事5で追加）。増やす時は `types.ts` の `SettingsMap` と `settings.ts` の検証の両方に追加

### 3.7 データ層の実装決定（工事1 検収時 2026-09-24）
- 配置: 純粋ロジック `src/lib/`、Dexie 層 `src/db/`。どちらも React を import しない。**公開 API の一覧は `reports/工事01_報告.md` 4章**（工事2以降はこれを見て使う）
- 評価の内部表現は **1〜50 の整数**（3.7 → 37）。`ratingFromNumber` は 0.1 刻みでない値（3.75 等）を**例外**にする（丸めない。画面側が 0.1 刻みで渡す）
- 日時は **ISO 8601 文字列（UTC、`toISOString()` 形式）**。工事8の取り込みでは他形式を同形式に正規化してから保存する
- 写真の並び順・表紙の正は `shop.photoIds` 配列。`photoIds` は写真 API（addPhoto / removePhoto / reorderPhotos）でのみ変更
- タグは `&[kind+normalizedKey]` で種別ごとに一意。正規化は NFKC＋小文字化＋空白整理のみ（ひらがな/カタカナ・長音は区別）。表示名は最初に登録した表記
- エラーは `ValidationError` / `RecordNotFoundError` / `PhotoLimitError` / `TagConflictError`。**DOMException と同名（NotFoundError, ConstraintError 等）は Dexie がトランザクション内で差し替えるため使用禁止**
- `createShop` は id・日時を指定できない（自分登録専用）。**取り込み用に id・日時・origin を保ったまま保存する関数は工事8で別に作る**
- 店を消してもどの店にも付いていないタグは残る。**孤立タグの削除はタグ整理画面（工事10）で行う**（自動削除しない）
- 名前順は `Intl.Collator('ja')`（漢字は読み順にならない）。**フリガナ項目は今は追加しない**（必要になれば任意項目として検討）
- インデックスは工事6の絞り込みに備えて version 1 で張り済み。未評価の店は rating インデックスに載らないため「未評価のみ」は全件走査で判定する想定

### 3.8 画像処理と画面の実装決定（工事2 検収時 2026-09-24）
- 画像のデコードは `<img>`＋object URL が主経路（失敗時のみ `createImageBitmap`）。**EXIF の向きはブラウザのデコードに任せ、自前で回転しない**（二重回転の事故防止。iPhone 実機で正しい向きを確認済み）
- 縮小の canvas は目標サイズ（≤1800px）で作る（元画像サイズの canvas は iPhone の面積上限に当たる）。大・小とも元画像から直接作る。写真は1枚ずつ処理（メモリ対策）
- 写真の失敗は `ImageProcessError`（`userMessage`＝「この写真は読み込めませんでした」）。DOMException と同名のエラー名は引き続き禁止
- 店＋写真の保存は `src/db/createShopWithPhotos.ts`（公開 API のみで組んだ1トランザクション）。**Dexie の親トランザクションは子 API が触る全テーブル（shops・photos・tags）を含める**こと（欠けると `SubTransactionError`）
- ID 生成 `newId()` は `crypto.randomUUID` が無い環境（LAN の http）で `getRandomValues` による UUID v4 にフォールバック（`src/lib/id.ts`）
- 画面切替は工事2では `App.tsx` の `useState`。**工事3で自作ハッシュルーターに置き換え済み**（3.9 参照）
- 写真の選択は `<input type="file" accept="image/*" multiple>` を隠して `click()`（`capture` 属性なし）。iPhone で「写真を撮る／フォトライブラリ／ファイルを選択」が出ることを確認済み
- 登録画面：保存ボタンは下部固定（`env(safe-area-inset-bottom)` 考慮）。保存失敗時はエラーの `name: message` を小さく表示（**診断用・仮**。残すか消すかは工事3以降で決める）
- 仮ホーム（`HomeScreen`）は保存確認用の一覧だった。**工事3で本物のタイル一覧に置き換え済み**（3.9）
- 配置：画面 `src/screens/`、部品 `src/components/`（PhotoPicker・BlobImage・Toast）、フック `src/hooks/`、スタイル `src/styles/app.css`
- fixture 生成 `scripts/make-fixtures.mjs`（`npm run fixtures`。EXIF Orientation=6 の JPEG を含む3枚を `e2e/fixtures/` に生成）

### 3.9 ルーターと一覧画面の実装決定（工事3 検収時 2026-09-25）
- **ルーターは自作のハッシュ方式**（ライブラリなし。`src/router/`）。純粋関数 `parseHash` / `formatHash`（`hashRoute.ts`）と、`useHashRoute()`（`useSyncExternalStore`）／`navigate()`（履歴に積む）／`replaceRoute()`（`history.replaceState`＋独自イベント。`hashchange` が発生しないため）
  - ルート：`#/`（一覧）／`#/register`（登録）／`#/shop/<id>`（店ページ。id は URI エンコード）。それ以外・壊れた形は一覧（例外を投げない）
  - 遷移ルール：「＋」・タイルタップ・「戻る」系は `navigate`。**保存後と削除後は `replaceRoute(home)`**（戻るで入力済みの登録画面に戻らない）。キャンセルは `history.back()` ではなく `navigate(home)`（`#/register` を直接開いた後に外へ出ないため）
  - どの画面でも再読み込みで同じ画面が出る。iPhone の左端スワイプで前の画面に戻れる（実機確認済み）
- **タイル一覧（`HomeScreen` を全面書き換え。デザインは花井さんが実機で A2 を選択 2026-09-25）**
  - CSS Grid・正方形タイル（`aspect-ratio: 1`）。**隙間 2px・角丸なし・画面の左右端まで**（`body` の左右 16px を `.tile-grid` の `margin-inline: -16px` で打ち消す）
  - 表紙は `getPhoto(photoIds[0])` の **`small` のみ**（`large` は一覧で読まない）。`<img loading="lazy" decoding="async">`、`object-fit: cover`
  - 下 60% に透明→黒 55% のグラデーション。店名は白・太字・最大2行（3列 13px／2列 15px）。**評価が未設定の店は☆を出さない**（「未評価」は店ページのみ）。☆は 3列 10px／2列 13px
  - 写真なしの店：店名の文字コード合計 mod 6 で6種の淡いグラデーション地を選び、店名を濃灰で中央に（`tileTone.ts`）
  - **列数（2列/3列）は利用者が切替ボタンで変える本機能**（花井さん判定「甲乙つけがたい」→固定しない）。値は `settings.columns` に永続化、既定は 3。ボタンの表示は**押した結果**（例「2列にする」。工事3a で変更）
  - 店ページから戻ったとき、前回の一覧とスクロール位置を即座に出し、裏で読み直す（モジュール変数に保持）
  - 見本切替（A1/A2）・見本データボタンは `import.meta.env.DEV` 限定で本番ビルドに含まれない。**A1 は不採用**（工事3a で撤去）。見本データ機能（`src/dev/sampleData.ts`）は後の工事の確認用に DEV 限定で残す
- **☆部品 `Stars`**（`src/components/Stars.tsx`）：`starFills` の5値を SVG 星5個の `clipPath` 幅で比例塗り。色は `--star-color`（#f5a623）／`--star-empty-color`（最終の色は工事10）。1〜50 だけを受け、未評価の表示は呼び出し側

### 4.1 一覧画面（ホーム）
- 上部：切替タブ「手札」「行きたい」（初期は手札）
- 上部：絞り込みバー — 場所（県・市・駅・エリア）／ジャンル／使い道／評価（例：4.0以上）／未評価のみ
- 並び替え：登録の新しい順（初期）／評価の高い順／名前順
- 上部右：**列数切替ボタン**（2列⇄3列。押した結果を表示。設定に保存）
- 本体：写真タイルのグリッド（**決定：A2＝隙間 2px・角丸なし・端まで**）。タイル＝正方形の表紙写真（一覧用小）＋下端グラデーション上に店名（白）＋☆（評価がある店のみ）
  - 写真のない店：店名から決まる淡色の地に店名を中央表示
  - 列数は利用者が切替（既定 3列）。2026-09-25 花井さん判定「A2 が圧倒的。列数は甲乙つけがたいので切替ボタンをそのまま本機能に」
  - タップで店ページへ
- 右下：「＋」（新規登録）
- 目標：スクロールが引っかからないこと（一覧用小画像のみ読み込む）

#### 4.1.1 工事6の決定（2026-09-26 花井さん回答＋相談役判断）
- **形：チップ列＋下から出る選択パネル**（花井さん選択。見本比較はしない）。「絞り込み」ボタン1つにまとめる案は、今何で絞っているかが見えにくいため不採用
- 上から：上部バー（題名・列数ボタン）→ **タブ「手札 12」「行きたい 3」**（件数つき、起動時は手札）→ **チップ列**（横スクロール：場所／ジャンル／使い道／評価／未評価のみ）→ **件数と並び順の行**（左「12件」、絞り込み中は「3件（12件中）」＋「条件を解除」、右「新しい順 ▾」）→ タイル
- 上部は固定しない（スクロールで一緒に流れる。写真を広く見せるため）
- チップ：条件が効いている時は塗りつぶしで中身を出す（「ラーメン」「ラーメン ほか1」「4.0以上」）。「未評価のみ」はパネルなしのオン/オフ
- パネル（下から）：**場所**（県の段＋エリアの段。市・駅の段は工事7で足す）／**ジャンル**／**使い道**／**評価**（指定なし・3.0/3.5/4.0/4.5以上 の1択）／**並び順**（新しい順・評価の高い順・名前順）。選んだその場で一覧に反映、下部「N件を表示」で閉じる、背景タップでも閉じる。履歴には積まない
- 候補は「今のタブの店」に1件以上付いているものだけ、件数つき（多い順→同数は名前順）。選択中のものは 0件でも出す（外せるように）
- **複数選択の意味（花井さん決定）**：県・エリア・ジャンルは「どれか」、使い道は「全部満たす」、種類をまたぐと「かつ」
- 評価と未評価のみは同時に効かない（片方を入れるともう片方を解除）
- 条件は両タブ共通（タブを切り替えても保持）。タブを切り替えたら一覧の先頭へ
- **記憶（花井さん決定）**：並び順は `settings.sortOrder` に保存。列数は今までどおり保存。タブと条件は店ページ等から戻った時は残るが、**アプリを開き直すと「手札・条件なし」**（友人に見せる時に「なぜか店が少ない」を防ぐ）
- **店名検索は入れない**（花井さん決定。店が増えて探しにくくなれば工事10で検討）
- 0件の表示：手札0件「＋から最初のお店を登録」／行きたい0件「行きたいお店はまだありません」／条件で0件「条件に合うお店がありません」＋「条件を解除」
- 作り：全店を一度読み、タブ・絞り込み・件数はメモリ上で計算（純粋関数を `src/lib/` に置き Vitest で固定）。並びは既存 `listShops({ sort })`。DB のスキーマ・既存 API は変えない（3.7 のインデックスは今回は使わない。数百件規模ではメモリ計算で十分）

### 4.2 登録・編集画面
- 目標：**写真＋店名だけなら10秒で保存**
- 上部：写真（撮影 or アルバムから選択、最大3枚、並べ替えで表紙変更）
- 店名（必須）→ 保存ボタンは常に見える位置に
- その下に任意項目（評価、場所、タグ、URL、メモ、手札/行きたい）
- 評価入力：0.1刻みで入れやすいUI（スライダー＋数値微調整など。見本で決める）
- 保存後は店ページへ

#### 4.2.1 工事5の決定（2026-09-26 花井さん回答＋相談役判断）
- 使い道タグの初期リストは「個室あり」「駐車場あり」の2つ（3.4）
- **評価入力は A 案（スライダー＋「−0.1」「＋0.1」ボタン）に決定**。見本比較はしない（花井さんが A のみ選択）。数値を大きく表示し、☆も一緒に動かす。未評価の状態を持ち、「未評価に戻す」ができる
- 場所の入力は**県（47択）とエリアタグ**だけ。市区町村の選択は工事7（3.5）。最寄り駅も工事7
- 登録と編集は**同じ入力フォーム**を使う。登録画面でも任意項目を店名の下に並べる（折りたたまない）。写真＋店名＋保存が一画面目に入り、10秒登録を壊さない
- 項目の並び：写真 → 店名 → 手札/行きたい → 評価 → ジャンル → 使い道 → 県 → エリア → GoogleマップURL → メモ
- 写真の並べ替えは各写真の「◀」「▶」ボタン（最大3枚なのでドラッグは作らない）。先頭が表紙。編集画面での写真の追加・削除・並べ替えは**保存を押すまで DB に反映しない**（キャンセルで元に戻る）
- タグ（ジャンル・エリア）は入力中に既存タグを候補表示。欄に触れただけでも既存タグを出す（新規作成より選ぶ方が楽な画面）。新しいタグは**保存時に作る**（キャンセルで孤立タグが増えないように）。使い道は既存タグをチップで並べてタップで付け外し、小さな「＋追加」で新規
- GoogleマップURL が http(s) でない時は入力欄の下に注意を出す（保存は止めない）
- 県を変えた時、既存の市（見本データ等）は消す（県と市の食い違い防止）。最寄り駅は触らない
- **保存後の行き先**：新規登録・編集とも店ページ（仕様どおり。工事2〜4の「登録後は一覧」は、店ページが無かった時の仮）
- 店ページ最下部（削除の上）に「編集」ボタン。「行きたい」の店だけ、☆の下に「行った！」ボタン → 手札（visited）にしてから編集画面を開く
- 編集中にキャンセル・戻るボタンを押した時、変更があれば確認を出す。iPhone の戻るスワイプは止められないため確認なしで破棄される（許容）
- ルート追加：`#/shop/<id>/edit`（編集画面）

### 4.3 店ページ
上から順に：
1. 写真（画面幅いっぱい、最大3枚を横スワイプ）
2. 店名
3. ☆（比例塗り）＋数値「3.7」
4. タグ（ジャンル・使い道）
5. 場所（県・市／最寄り駅／エリア）
6. 「Googleマップで開く」ボタン（URLがある時のみ）
7. メモ
8. 「編集」「この店を送る」

- 一画面目は写真・店名・評価で埋まり、下にスクロールで詳細、を目安にする
- 「行きたい」の店には「行った！」ボタン → 押すと status を visited にし、編集画面を開いて写真・評価の追加を促す（昇格）。**編集画面と一緒に工事5で作る**

#### 4.3.1 工事4の決定（2026-09-26 花井さん回答＋相談役判断）
- **見本比較（実機切替）**：写真の縦横比（**1:1**／**4:5**）× 上部の出し方（**バー**＝写真の上に「← 戻る」のバー／**重ね**＝写真を画面最上部から出し、戻るボタンを写真に重ねて浮かせる）の 2×2。切替チップは DEV 限定、判定後に工事4aで固定（工事3→3a と同じ流れ）。本番の既定は判定までは 1:1×バー
  - **判定（2026-09-26 花井さん、iPhone 実機）：上部は「重ね」、比率は「4:5」**（比率は「迷うが 4:5」）。iPhone の戻るスワイプと写真の横スワイプの衝突なし、実機確認の手順はすべて問題なし。工事4a で 1:1・バーを撤去して固定
- 写真スワイプは**ライブラリなし**（CSS の scroll-snap）。2枚以上のときだけ位置を示す点を出す。写真は枠いっぱいに切り抜き（`object-fit: cover`）。店ページは `large` を使う
- **写真タップの全画面拡大（ピンチ）は作らない**。要否は工事10で判断
- 「編集」（工事5）・「この店を送る」（工事8）は**作る工事まで出さない**（押しても何も起きないボタンは置かない）。削除はページ最下部に控えめに残す
- 空の項目は見出しごと出さない（未評価だけは「未評価」と出す）。最寄り駅の表示は駅マスタと一緒に工事7
- Googleマップのボタンは `http:`/`https:` の URL のときだけ出し、別タブで開く（`javascript:` 等は出さない）。メモは改行を保って表示し、URL の自動リンクはしない
- タグ・場所・URL・メモはまだ入力画面が無い（工事5）ため、確認は DEV 限定の見本データ（「見本用に増やす」を拡張）で行う

### 4.4 ☆表示ルール
- ☆5個。評価値をそのまま塗り量にする（3.7 → ☆3個全塗り＋4個目を70%塗り）
- 数値を必ず併記（小数1桁）
- 未評価は「未評価」と表示（☆0個と区別する）。**ただし一覧タイルでは未評価の店に何も出さない**（工事3決定。タイルをすっきりさせる）

### 4.5 お裾分け・バックアップ画面
- 書き出し：1店（店ページから）／複数選択（一覧で選択モード）／全店（バックアップ）
- 共有：Web Share API でファイルを共有メニューに渡す（LINE・AirDrop・メール等）。非対応環境ではダウンロード
- 取り込み：「取り込む」→ファイル選択
  - 他人から来た店は origin=shared、status=wishlist で取り込む（自分のバックアップ復元時は元の状態のまま）
  - 同じidの店が既にある場合：スキップ／上書きを選択（初期はスキップ）
  - 相手のタグはそのまま取り込み（正規化キーが一致すれば既存タグに合流）。揺れは整理画面で統合
- バックアップの促し：最終書き出しから30日（仮）で一覧画面に控えめな案内
