## 2. やったこと

- **ルート**: `#/shop/<id>/edit`（`{ screen: 'edit', id }`）を追加
- **共通フォーム** `ShopForm`: 登録画面と編集画面が同じ部品を使う

  - 使い道: 既存タグのチップをタップで付け外し、「＋追加」で新しい使い道

- **保存処理**: 新規登録と編集を、それぞれ1トランザクションで行う関数（`src/db/saveShopForm.ts`）

- **画面のつなぎ**

## 4. フォームの作り

### 部品の分け方
- `ShopForm`（画面全体）の中で、`RatingInput`・`TagInput`（ジャンル・エリア）・`UseTagPicker` と既存の `PhotoPicker` を並べる
- 値は1つの `ShopFormValues`（`src/lib/shopForm.ts`）にまとめ、写真は `usePhotoDrafts` が持つ
- 店名の入力欄は、今までと同じ見た目・placeholder「店名（必須）」のまま
  - 見出しは画面に出さず、読み上げ用の「店名」だけ（placeholder が見出しを兼ねるため）
  - ほかの項目には小さな見出しを付けた

### 登録と編集の違いの吸収（`ShopForm` の Props だけで違いを出す）

| | 登録 `RegisterScreen` | 編集 `EditScreen` |
|---|---|---|
| 題名 | お店を登録 | 店を編集 |
| 初期値 | `emptyShopForm()`（手札・未評価・空） | `shopFormFromShop(店, タグ)`（存在しないタグ ID は飛ばす） |
| 写真の初期値 | なし | 保存済みの写真（`photoIds` の順、`small` を表示） |
| キャンセルで確認 | しない（今までどおり一覧へ） | 変更があれば「変更を破棄しますか？」 |
| 保存 | `createShopFromForm` → 店ページ | `saveShopEdit` → 店ページ |

### 変更の有無の判定
次のどちらかなら「変更あり」とします。
- **値**: 最初の値と今の値を `sameShopForm` で比べる（純粋関数・単体テストあり）。名前は1文字でも違えば変更。タグは正規化キーの並びで比べる
- **写真**: 写真枠の並び（保存済みは `saved-<id>`、新規は枠ごとの番号）が最初と違う。削除・並べ替え・追加（処理中・失敗した枠も含む）のどれでも変更になる

同じ値に戻した場合（例: 評価を 3.7 → 3.8 → 3.7）は「変更なし」になり、確認は出ません。

### 細かい決め事
- **県**: `<select>`（先頭「未選択」＋47件）。47件に無い値の店（将来の取り込み等）は、その値を先頭に足して選べるままにする
- **県を変えた時**: 市を消す判定は保存処理の中で行う（DB の今の県と違う時だけ `city: undefined`。`stationId` は渡さない）
- **GoogleマップURL**: `type="url"`・`inputmode="url"`。http(s) でない時は欄の下に注意を出す
  - ブラウザの入力チェックで保存が止まらないよう、フォームに `noValidate` を付けた（**保存は止めない**）
  - 保存時は前後の空白を除く
- **メモ**: `<textarea rows=4>`。改行はそのまま保存（空白だけなら未設定）
- **タグ入力の Enter**: フォームの送信にならないように止めている。日本語入力の変換中（`isComposing`）の Enter は無視する
- **評価**
  - スライダーは `min=1 max=50 step=1` で、値は常に `clampRating` を通す（0.1 刻みでない値が入る経路は無い）
  - 未評価の時はスライダーを 35% の濃さで表示。触れる（`pointerdown`）と、動かさなくても 3.0 で評価が付く
  - 「−0.1」「＋0.1」は未評価なら 3.0 を起点に動く
  - スライダーは左右の ± ボタンの内側にあるので、画面端から 70px 以上離れている（戻るスワイプ対策）
- **表紙**: 先頭の「保存対象の写真」（新規の処理済み or 保存済み）に「表紙」ラベル。「◀」は先頭、「▶」は末尾には出さない

## 5. 保存処理の作り（`src/db/saveShopForm.ts`）

- **トランザクションに含めたテーブル**: 新規・編集とも `shops`・`photos`・`tags`
  - 子の API（`createShop`・`updateShop`・`addPhoto`・`removePhoto`・`reorderPhotos`・`findOrCreateTag`・`createShopWithPhotos`）が触るテーブルをすべて含めている
  - settings は触らないので含めていない
  - 初期タグの `seedUseTags` は別のトランザクション（`tags`・`settings`）
- **新規 `createShopFromForm`**: 新しいタグを `findOrCreateTag` で作る → 既存の `createShopWithPhotos`（変更なし）を同じトランザクションの中で呼ぶ
- **編集 `saveShopEdit`** の手順
  1. 今の店を読む（無ければ `RecordNotFoundError`）
  2. 新しいタグを作る
  3. `updateShop`（名前・区分・評価・県・URL・メモ・タグ3種。県が変わった時だけ `city: undefined`）
  4. 残さない写真を `removePhoto`
  5. 足した写真を `addPhoto`
  6. 最終の並びで `reorderPhotos`
  - 削除を追加より先にするので、「1枚消して1枚足す」は3枚の上限に当たらない
- **失敗時に元のままになることの確かめ方**（fake-indexeddb の単体テスト。前後の店のレコード全体・写真の中身・タグ一覧を比べる）
  - 写真が上限を超える（3枚＋1枚）→ `PhotoLimitError`。名前の変更も新しいタグも残らない
  - 店に無い写真 ID が並びに入っている（古い画面から保存した想定）→ `reorderPhotos` の `ValidationError`。途中の `updateShop` も取り消される
  - 保存前に店が消えていた → `RecordNotFoundError`。タグは作られない
  - 新規登録で店名が空白・写真4枚 → 店もタグも残らない
- 「新しいタグは保存時にだけ作られる」も単体テスト（保存前は既存タグだけ）と e2e（キャンセル後に `listTags` にも候補にも無い）で確認した

## 6. 編集画面からの戻り方（`App.tsx`）

- 店ページの「編集」「行った！」から開く時は、`editOpenedFrom`（`useRef`）にその店の ID を覚えてから `navigate(編集)` する
- 保存後・キャンセル後の戻り方
  - `editOpenedFrom` が今の店の ID と同じ → `history.back()`（履歴は「…→店ページ→編集」なので、1つ戻れば店ページ）
  - 違う（URL を直接開いた・再読み込みした＝ ref が空）→ `replaceRoute(店ページ)`。編集画面の履歴を店ページで置き換えるので、「戻る」で編集画面に戻らない
- ref は一覧・登録画面に移った時に消す。再読み込みでも消える
- 迷った点: 「編集 → 戻るスワイプで店ページ → 進むで編集画面」の時も ref は残ります。この場合も直前は店ページなので `history.back()` で正しく店ページに戻ります
- 新規登録の保存後は `replaceRoute(店ページ)`（登録画面の履歴を置き換える）。そこから戻ると一覧（e2e で確認）

7. **行った！**: 行きたいの店に「行った！」→ 押すと編集画面（区分は手札）→ キャンセル → 手札のまま「行った！」が消え、再読み込みしても出ない
8. **編集画面を直接開く**: URL で開いて再読み込み → 保存 → 店ページ → ブラウザの戻るで編集画面に戻らない。存在しない ID の編集画面 →「この店は見つかりません」→「一覧へ戻る」
9. **http でない URL**: 注意が出る（https にすると消える）が保存できる → 店ページに地図ボタンが無い、DB には入力した文字列のまま

## 9. スライダーの e2e の操作について

Playwright は `<input type="range">` に `fill` できません。そのため、スライダーの値を設定して `input` イベントを出す関数で操作しています。React は同じイベントで値を受け取るので、指で動かした時と同じ経路を通ります。指の感じ（大まかに合わせやすいか、スクロールと誤作動しないか）は実機で確かめてください（12章 手順3）。

## 11. 設計上の判断・迷った点

1. **`usePhotoDrafts` と `PhotoPicker` は広げた**（新しいフックで包まなかった）
   - 包む方法だと、保存済みと新規の写真を1本の並びで扱うために、中の配列を外から並べ替える仕組みが要ります。この方が複雑になると判断しました
   - 追加だけにして既存の処理には手を付けていません。登録画面の既存 e2e（4枚目の拒否・EXIF・透過・寸法）は変更なしで通っています
2. **タグの候補を閉じるのは 200ms 遅らせた**: 入力欄から指を離した瞬間に候補を消すと、候補をタップしても反応しないことがあるためです
   - 候補のボタンは `mousedown` で入力欄のフォーカスを外さないようにしてあります
   - 候補を選んだ後は入力欄にフォーカスを戻すので、続けて選べます
   - iPhone でキーボードが一度閉じて開き直す動きになるかは実機で見てください
3. **「未評価に戻す」を数値の右に置いた**: 評価がある時だけ出ます。未評価の時は大きな「未評価」の文字だけです
4. **使い道の新しいタグの並び**: 既存の使い道（名前順）の後ろに、このフォームで足したものを並べます。保存後は既存タグになるので、次からは名前順の中に入ります
5. **初期タグを作るのは DB を開いた直後、最初の画面を出す前**: 作り終える前に登録画面を開くと、初期タグがチップに出ない可能性があるためです（数ミリ秒で終わる）。失敗してもログだけ出して画面は出します
6. **初期タグの名前の見本タグは、見本が作ったものでも消さない**: 見本の「個室あり」が付いた店を消しても、「個室あり」は残ります（初期タグと同じ名前なので区別しない）
7. **店ページの「編集」**: 副ボタン（灰色）で中央に置き、最小幅 160px にしました。幅いっぱいにすると「Googleマップで開く」と同じ見た目になり、区別しにくいためです
8. **登録画面の一画面目**: 390×844 で「写真を追加」「店名」「保存」に加え、評価〜エリアまで見えます。写真を3枚入れても、店名は保存バーより上に収まります
9. **iPhone のキーボードと下部固定の保存ボタン**: 保存バーは今までどおり `position: fixed`（下端）です。iOS Safari ではキーボードを出すと、保存バーがキーボードの上に乗るか、隠れるかが版によって違います
   - 入力欄が保存バーの裏に隠れないよう、フォームの下に保存バーの高さ分の余白はあります
   - メモ・URL を入れる時の見え方は実機で確認してください（12章 手順7）

## 12. 花井さんの iPhone 実機確認手順

1. PC で `git pull` → `git switch work/05-edit` → `npm run dev` → iPhone の Safari で `Network:` の URL を開き、再読み込み
2. **新規登録**
   - 写真＋店名だけで保存 → 店ページが開く（戻ると一覧）
   - もう1件、評価・タグ・県・エリア・URL・メモ・「行きたい」まで入れて保存 → 店ページに全部出る
3. **評価の入れやすさ**
   - スライダーで大まかに合わせ、±0.1 で狙った値（例 3.7）にできるか
   - スライダーを触る時に、戻るスワイプやページのスクロールが誤作動しないか
4. **タグ**
   - 欄に触れると既存タグの候補が出る、途中まで打つと絞られる、新しいタグを作れる
   - 使い道に「個室あり」「駐車場あり」が出ている
   - （見本データを作り直すと、見本のジャンル・エリアも候補に出ます）
5. **編集**
   - 写真の ◀▶ で表紙を変えて保存 → 店ページと一覧の表紙が変わる
   - 編集して「キャンセル」→「変更を破棄しますか？」→ OK → 元のまま
6. **行った！**:「行きたい」の店で「行った！」→ 編集画面が開く → 写真と評価を足して保存 → 手札の店になっている（「行った！」が消える）
7. **キーボード**: キーボードが出た時に、保存ボタンや入力欄が隠れて困らないか（特にメモ・URL）
8. 報告してほしいこと（相談役経由で）: 評価の入れやすさ、タグ候補の出方（タップしにくい・キーボードが閉じる等）、◀▶ の押しやすさ、キーボードでの困りごと、登録の時間（写真＋店名だけ）
