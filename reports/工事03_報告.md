## 4. ルーター

| ルート | ハッシュ | 画面 |
|---|---|---|
| home | `#/`（空・`#` も home） | タイル一覧 |
| register | `#/register` | 登録画面 |
| shop | `#/shop/<id>`（id は URI エンコード） | 仮の店ページ |
| それ以外・壊れた形（`#/foo`、`#/shop/`、`#/shop/a/b`、不正なエスケープなど） | — | home（例外は投げない） |

- **navigate（履歴に積む）**: ホーム →「＋」、キャンセル → ホーム、タイル → 店ページ、店ページの「← 戻る」／「一覧へ戻る」
- **replaceRoute（積まずに置き換える）**: 保存後 → ホーム、店の削除後 → ホーム
  - 保存後に「戻る」を押しても、入力済みの登録画面には戻らない（e2e で確認）
- **キャンセルで `history.back()` を使わない理由**: `#/register` を直接開いて再読み込みした場合に、戻るとアプリの外へ出てしまうため。キャンセルは常に `navigate(home)`
- **再読み込み**: どの画面でも同じ画面が出る（`#/register`・`#/shop/<id>` で確認済み）
- **戻る**:
  - ブラウザの戻る（iPhone では画面左端からのスワイプ）で、直前の画面に戻る（店ページ → 一覧 → 戻る で店ページ、を e2e で確認）
  - 一覧のスクロール位置は、店ページから戻った時に元の位置に戻す（前回の一覧を覚えておき、すぐ描いてから新しい内容に差し替える）。**この挙動は e2e では確認していません**。9章の手順7で実機確認をお願いします
- **補足**: `history.replaceState` では `hashchange` が発生しないため、`replaceRoute` は独自のイベントを発行し、`useHashRoute` はその両方を購読しています

## 5. タイル

### A1 と A2 の違い（`.home-screen` に付くクラスだけ。TSX の分岐はなし）

| | A1（`tiles-a1`、カード寄り） | A2（`tiles-a2`、インスタ寄り） |
|---|---|---|
| 隙間 | 8px | 2px |
| 角丸 | 12px | なし |
| 左右 | body の左右 16px の余白をそのまま使う | 一覧（`.tile-grid`）だけ `margin-inline: -16px` で打ち消し、画面の端まで表示 |

- 列数は `.cols-2` / `.cols-3` のクラスと、グリッドの `--cols`（`grid-template-columns: repeat(var(--cols), minmax(0, 1fr))`）で決まる
- 共通の見た目:
  - 正方形（`aspect-ratio: 1`）で、表紙の **small だけ**を `object-fit: cover` で敷く
  - 下 60% に透明から黒 55% へのグラデーション
  - 店名は白文字・太字で、3列は 13px、2列は 15px。どちらも最大2行（`-webkit-line-clamp`）
  - ☆の大きさは3列で 10px、2列で 13px（CSS 変数 `--star-size`）
  - 評価が無い店は☆を出さない
- `<img>` には `loading="lazy"` と `decoding="async"` を付けた

### 写真なしタイルの色の決め方
- 店名の文字コード（UTF-16）の合計を 6 で割った余り（0〜5）で、淡い2色のグラデーションを6種類から選ぶ（オレンジ・黄・緑・青・紫・ピンク系）
- 店名が同じなら、いつも同じ色になる
- 店名は濃い灰色（#3b3632）で中央に置き、最大3行。☆は店名の下

### ☆の描き方
- `starFills(rating)` の5つの値（0〜1）を使い、星ごとに SVG を1つ描く
- 灰色の星の上に、同じ形の塗った星を `clipPath` の矩形で左から切り抜いて重ねる
- 矩形の幅は、星の図形の左端から右端までの範囲に塗り量を掛けて決める（星の外側の余白は含めないので、0.1 でも見える）
- 色は `--star-color`（#f5a623）と `--star-empty-color`。写真の上では空の星を白 40% にした
- 右に `ratingToText` の数値を出す。`aria-label` は「評価 3.7」
- clipPath の id は `useId()` から記号を取り除いて作った（`url(#…)` の参照が壊れないように）

### タイル1枚の表示幅と必要画素数（iPhone 12〜15 の画面幅 390px、画素倍率 3 で計算）

| | タイル幅（CSS px） | 必要画素数（×3） | small で使える画素数 | 足りているか |
|---|---|---|---|---|
| A1・3列 | (390 − 32 − 16) / 3 ≒ **114** | 342 | 300（4:3 の写真）／ 400（正方形） | 4:3 はやや不足（88%） |
| A1・2列 | (390 − 32 − 8) / 2 = **175** | 525 | 300 ／ 400 | 不足（57%） |
| A2・3列 | (390 − 4) / 3 ≒ **129** | 386 | 300 ／ 400 | 4:3 は不足（78%） |
| A2・2列 | (390 − 2) / 2 = **194** | 582 | 300 ／ 400 | 不足（52%） |

- **注意**: タイルは正方形に切り抜く（cover）ので、効いてくるのは small の**長辺ではなく短辺**です。iPhone の写真（4:3）なら small は 400×300 なので、使える画素数は **300px** です。依頼文の見立て（長辺 400px）より厳しく、**3列でも少し甘く見える可能性**があります
- 参考として、写真の短辺を必要画素数に合わせると、small の長辺は次のくらいが要ります（`imageSizes.ts` はこの工事では変更していません）
  - 3列（A1）: 約 460px
  - 3列（A2）: 約 520px
  - 2列: 約 700〜780px
- 工事3a で、選ばれた案に合わせて決めるのが良いと考えます（8章・9章）

## 8. 設計上の判断・迷った点

1. **A2 の端まで表示と body の余白**: `index.css` の body の左右 16px はそのままにし、A2 の時だけ一覧のグリッドに `margin-inline: -16px` を付けて打ち消しました。登録画面・店ページの見た目は変わりません。上部バー（見出し・列ボタン）は 16px 内側のままです
2. **読み込み中の表示**
   - 初回は薄い灰色の正方形を9枚出す（真っ白にしない）
   - 2回目以降（店ページから戻った時など）は前回の一覧をすぐ出し、裏で読み直して差し替える
   - 列数の設定を読み込む前は、グリッドを灰色の正方形のままにした（3列 → 2列と一瞬ずれるのを防ぐため）
3. **表紙の取得回数**: 一覧を読み込むたびに、店ごとに `getPhoto(photoIds[0])` を1回呼び、使うのは small だけです（large は読みません）。店ページから戻るたびに全店分を読み直しますが、small は数KB〜数十KB なので、数百店までは問題ない見込みです。件数が大きくなって重ければ、工事6前後でキャッシュを検討します
4. **列数の保存は非同期**: 切替ボタンを押すと表示はすぐ変わり、設定の保存（IndexedDB）はその後に行われます。e2e では保存完了を待ってから再読み込みしています。押した直後（数ミリ秒以内）に Safari を閉じると、保存されない可能性があります。実用上は問題ないと考えています
5. **見本データ**
   - 依頼は「評価は 1〜50 のランダム」でしたが、7件に1件を未評価にしました（☆が無いタイルの見え方も確認できるように）
   - 4件に1件を写真なしにしました
   - 複製には `createShopWithPhotos`（`createShop` と `addPhoto` を組み合わせた既存の関数）を使いました
6. **開発用コードを本番から外す方法**: `{import.meta.env.DEV && <DevSampleBar … />}` と書くと、本番ビルドでは条件が `false` に置き換わり、見本バーとその関連コードが取り除かれます。A1/A2 の初期値も `import.meta.env.DEV ? loadTileVariant() : 'a1'` なので、本番では常に A1 です
7. **タイルの要素**: `<button>` の `aria-label` を店名にしました。見出しの「グルメカード」は一覧に1つだけです（smoke テストの `getByText('グルメカード')` が他の文字と重複しないように）
8. **見本の撮影を `npm run e2e` から外した理由**: e2e のたびに PNG が書き換わると、`git status` が毎回汚れるためです。撮影は `npm run shots` で行います
9. **使われなくなった CSS**: 工事2の仮ホームのスタイル（`.shop-row` など）が `app.css` に残っています。既存ファイルの変更を最小にするため今回は消していません。工事3a か工事10で整理します
10. **e2e で直したこと**
    - 削除や戻るの後の URL の確認は、自動で待つ `toHaveURL` にした（最初はクリック直後に URL を読んで、非同期の削除より先に判定して落ちたため）
    - 列数のテストは、IndexedDB への保存を待ってから再読み込みするようにした
