#### 1-1. 画像の縮小ロジック `src/lib/`

**定数**（`src/lib/imageSizes.ts`。後から変えられるよう1か所に集める）
- 一覧用（小）: 長辺 **400px**、JPEG 品質 **0.80**
- 店ページ用（大）: 長辺 **1800px**、JPEG 品質 **0.85**（2026-09-24 花井さん決定。仕様書 3.3 の 1600〜2000 の中間）
- 元画像が目標より小さい場合は**拡大しない**（そのままの寸法で JPEG 化のみ）

**純粋関数**（`src/lib/imageSize.ts`。Node の Vitest で単体テストする）
- `fitLongSide(width, height, longSide) → { width, height }`：長辺を `longSide` に合わせ、短辺は比率維持で四捨五入、最小 1px。元が小さければそのまま返す

**ブラウザ側の処理**（`src/lib/image.ts`。canvas を使うため単体テストは不可、e2e と実機で確認）
- `processImageFile(file: File | Blob) → Promise<{ small: Blob, large: Blob, width: number, height: number }>`（戻り値はそのまま `addPhoto` の第2引数に渡せる形。`width/height` は large の寸法）
- デコードは `<img>` 要素＋`URL.createObjectURL` で行う（`createImageBitmap` は Safari で EXIF 向きや HEIC の扱いに差があるため主経路にしない。使うなら `<img>` 経路のフォールバックとして）。使い終わった object URL は必ず `revokeObjectURL`
- **EXIF の撮影向き**：現行ブラウザは `<img>` のデコード時に向きを適用し、`naturalWidth/naturalHeight` も向き適用後の値になる（CSS `image-orientation: from-image` が既定）。この前提で「デコード後の寸法を基に縮小し、canvas に描く」だけにし、**自前で EXIF を読んで回転する処理は書かない**（二重回転の事故を防ぐ）。実機で向きがおかしければ、その事実を報告書に書いて相談役の判断を待つ
- 縮小は「大」を元画像から直接、「小」も元画像から直接（大から作り直さない）。`ctx.imageSmoothingQuality = 'high'`。canvas は**目標サイズ（≤1800px）で作る**（元画像サイズの canvas は iPhone の canvas 面積上限に当たるので作らない）
- JPEG 化の前に canvas を白で塗る（透過 PNG の透過部分が黒くなるのを防ぐ）
- 出力は `canvas.toBlob('image/jpeg', quality)`。`toBlob` が null を返す・デコードに失敗する場合は、利用者向けの日本語メッセージを持つ独自エラー（例 `ImageProcessError`。**DOMException と同名の名前は禁止**）で reject する
- HEIC：iPhone の Safari は `<input type="file">` で選んだ HEIC を JPEG に変換して渡すか、そのまま渡してもデコードできる見込み。**特別な対処は書かず**、失敗したら上のエラーメッセージで「この写真は読み込めませんでした」と出す。実機で結果を確認する（下記 4章）

#### 1-2. 画面

**画面切替**（`src/App.tsx`）
- ルーティングライブラリは**まだ入れない**。`useState` で `{ screen: 'home' } | { screen: 'register' }` を持ち、切り替えるだけの薄い実装にする。切替の実体は `App.tsx` の1か所に閉じ込め、後の工事でルーターに置き換えやすくしておく（GitHub Pages ではハッシュ方式が要る見込み。判断は工事3以降）

**仮ホーム**（`src/screens/HomeScreen.tsx`。**工事3で本物のタイル一覧に置き換える前提の仮画面**。見栄えは作り込まない）
- 見出しに「グルメカード」を表示（工事0の e2e スモークテストがこの文字を探すため。**`e2e/smoke.spec.ts` は変更せずそのまま通す**）
- `listShops()`（既定の新しい順）で全店を並べる。1行＝表紙サムネイル（`getPhotosForShop` の先頭の `small` を object URL で表示。写真なしは灰色の枡）＋店名＋写真枚数＋登録日時（ローカル時刻で `MM/DD HH:mm` 程度）
- 各行に「削除」ボタン（`window.confirm` で確認 → `deleteShop`）。実機で試し登録を消すためのもので、これも仮
- 右下に「＋」の丸ボタン（登録画面へ）。0件のときは中央に「＋から最初のお店を登録」程度の案内
- object URL はアンマウント時・一覧更新時に `revokeObjectURL` する（漏らすと iPhone のメモリを食う）

**登録画面**（`src/screens/RegisterScreen.tsx`。仕様書 4.2 の「最小」版）
- 上部：写真エリア。**「写真を追加」ボタン1つ**＝`<input type="file" accept="image/*" multiple>`（`capture` 属性は付けない。iPhone は「写真を撮る／フォトライブラリ／ファイルを選択」の選択肢を自動で出す。Android も同様のチューザーが出る）。ボタンを押すと隠した input を `click()` する
  - 選んだ瞬間に `processImageFile` を**1枚ずつ**走らせ、処理中はその枡に「処理中…」を出す（同時に複数枚デコードしない。iPhone のメモリ対策）
  - 処理済みの写真は `small` を object URL でサムネイル表示。各サムネイルに「×」（取り消し）。**先頭が表紙**と分かる小さなラベルを付ける。**並べ替えは作らない**（工事5）
  - 4枚目以降は受け付けず「写真は3枚までです」と表示（`MAX_PHOTOS_PER_SHOP` を使う）
  - 処理に失敗した写真はその枡にエラーメッセージを出し、他の写真と保存は続けられる
- 店名：`<input type="text">`、`placeholder="店名（必須）"`、`enterKeyHint="done"`。iPhone で自動大文字化・自動修正が邪魔にならないよう `autoCapitalize="off"` `autoCorrect="off"`
- **「保存」ボタンは画面下部に固定**（`position: sticky` または fixed。iPhone Safari の下部ツールバーに隠れないよう `env(safe-area-inset-bottom)` を考慮）。店名が空白のみ、または写真の処理中は無効
- 保存処理：`createShop({ name })` → 処理済み写真を順に `addPhoto(shop.id, …)`。**店の作成と写真の追加は1つのトランザクションで包む**（`db.transaction('rw', db.shops, db.photos, …)` の中で公開 API を呼ぶ。Dexie は入れ子のトランザクションを親に合流させる）。途中で失敗したら店も残らないこと。入れ子でうまく行かない場合は無理に書き換えず、理由を報告書に書いて「店だけ残る可能性」を保留事項にする
- 保存後：仮ホームに戻り、一番上に今の店が見えること。「保存しました」の短い表示（2秒程度で消える）があればよい。`status` は既定（`visited`）のまま。「行きたい」切替や評価などの任意項目は**この工事では作らない**（工事5）
- 左上に「キャンセル」（仮ホームへ戻る。処理済み写真の object URL を revoke）

**共通**
- スマホ幅（390×844）で崩れないこと。タップ対象は 44px 以上。文字サイズは iPhone で自動ズームが起きないよう input は 16px 以上
- 見栄えは「工事3以降で本気を出す」前提で最小限。ただし登録画面は今後もこの形を土台にするので、素直な構造（部品に分けやすい）で作る
- DB が開けない（プライベートブラウズ等）場合は、真っ白にせず「この環境ではデータを保存できません」と表示する（`db.open()` の失敗を `App.tsx` で捕まえる程度でよい）

#### 1-3. テスト

**単体（Vitest）**
- `fitLongSide`：横長・縦長・正方形、元が小さい場合は拡大しない、極端な比率（例 6000×100 → 短辺 1px 以上）、丸め

**e2e（Playwright、Chromium 390×844）** `e2e/register.spec.ts` を新規追加。既存の `smoke.spec.ts` はそのまま通す
- fixture 画像は `e2e/fixtures/` に置き、**Node スクリプト `scripts/make-fixtures.mjs` で生成**して同スクリプトもコミットする（新しい依存は入れない。Playwright の Chromium でページ内 canvas から PNG/JPEG を生成して保存する方法でよい）。用意するもの：
  1. 横長 JPEG 3000×2000（縮小の確認用。単色でなく、向きが分かる模様入り）
  2. 縦長 PNG 800×1200（透過あり。拡大しない＋透過が白になる確認用）
  3. **EXIF Orientation=6（90°回転）の JPEG 2000×1500**：1 の JPEG に APP1（Exif）セグメントを差し込む。手書きの Exif ヘッダで十分（IFD0 に Orientation タグ 0x0112 だけ）。**難しければ理由を書いて実機確認に委ねてよい**（必須ではないが、できれば）
- 確認する内容：
  - 仮ホーム 0件 → 「＋」→ 登録画面。店名空で保存ボタンが無効
  - fixture 1・2 を `setInputFiles` で選ぶ → サムネイルが2枚出る → 店名入力 → 保存 → 仮ホームに1件、店名と枚数「2」が出る

  - ページ内で IndexedDB を直接読み（`page.evaluate` で Dexie を通すか `indexedDB` 直接）、photos が2件、fixture 1 の `large` は 1800×1200、`small` は 400×267、fixture 2 の `large` は 800×1200（拡大していない）、すべて `type === 'image/jpeg'`

  - fixture 3 を用意できた場合：保存後の `large` が **縦長（1200×1600 相当）**になっていること
