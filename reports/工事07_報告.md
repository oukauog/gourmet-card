## 2. やったこと

- **原データ**を `data-src/` に置いた
  - 駅データ.jp の CSV（花井さんが置いたもの）

- **マスタの読み込み**（必要な時だけ別ファイルとして読む・使い回す）と**純粋関数**（候補・表示名・自動補完・市の一覧）
- **登録・編集フォーム**
  - 項目の並び: 最寄り駅 → 県 → 市
  - 最寄り駅は文字入力＋候補、市は選択式
  - 駅を選ぶと、空いている県・市を埋める
  - 県を変えると市を空にする
  - 出典表記
- **保存**: フォームの県・市・駅をそのまま保存する（保存関数の「県が変わったら市を消す」を外した）
- **店ページ**: 場所の欄を「県 市」→「駅」→「エリア」の縦並びにした
- **一覧の場所パネル**: 市・駅の段を足した
  - 県を選ぶと、市・駅の候補がその県だけになる
  - チップの数え方を合わせた
- **見本データ**（DEV 限定）: 富山・高岡・金沢の駅を付けた
- **テスト**: 単体 +34件、e2e `station.spec.ts` 10件（新規）。既存 e2e は**変更なし**で全部通った

**まとめ方**（「最初の行」の決め方を少し変えた。理由つき）
- 名前・県・住所は、**グループコードと同じ駅コードの行（代表の駅）**から取ります（運用中の場合）
- 代表の駅が運用停止の時（63グループ）は、**名前の一番短い行**（同じ長さなら `e_sort` 順 → 駅コード順）から取ります
- 単純に `e_sort` の最初の行にすると、一部のグループで名前がずれるため、この決め方にしました
  - 「魚津」のグループが「新魚津」（地鉄）になる
  - 「金沢」のグループが「北鉄金沢」になる
  - 「淡路」が「JR淡路」になる
- 同じグループの中で県が違う例は無かった

## 5. 読み込みの作り

- **いつ読むか**
  - **一覧**: 今のタブの店のどれかに駅が付いている時だけ、駅マスタを読む（駅の段の名前が要るため）。付いていなければ読まない（e2e で `stations.json` の通信が無いことを確認）。読み終わるまで駅の段は出ない
  - **店ページ**: その店に駅が付いている時だけ読む
  - **登録・編集フォーム**: 開いた時に駅マスタと市区町村マスタを読む
- **作り**
  - `src/data/geoMaster.ts` の `loadStationMaster()`・`loadCities()` が `import('./stations.json')` 等で別ファイルとして読む
  - ビルドでは `stations-*.js`・`cities-*.js` の別ファイルになる
- **使い回し**
  - 一度読んだ Promise と結果をモジュール変数に持ち、2回目からは読まない
  - 読み終わっていれば、画面は最初の描画から「読めた」状態で出る（読み込み中のちらつきが無い）
- **失敗した時**
  - 覚えた Promise を捨てるので、次に画面を開いた時にもう一度読む
  - フォーム: 最寄り駅の欄は押せなくなり、「駅の一覧を読み込めませんでした」と出る。**ほかの項目と保存はそのまま使える**
  - 保存済みの駅は「（見つからない駅）×」と出るので、外すことはできる
  - 一覧: 駅の段が出ないだけ
  - 店ページ: 駅の行が出ないだけ
- **大きさ**（ビルド後）: 駅 231.6 kB（gzip 75.4 kB）、市区町村 22.4 kB（gzip 8.9 kB）
  - LAN の開発サーバーでは一瞬で読めます

## 6. 候補の作り

- **正規化**（入力と駅名の両方）
  - NFKC → 空白をすべて除く → 「ヶ」を「ケ」に
  - 入力は末尾の「駅」も外す
  - 例:「阿佐ヶ谷」で「阿佐ケ谷」、「幡ケ谷」で「幡ヶ谷」、「高岡駅」で「高岡」、半角カナ「ﾄﾔﾏ」は全角「トヤマ」
  - 大文字・小文字は同じとみなしていません（依頼にないため。駅名の英字はほぼ大文字）
- **並び**
  - 前方一致 → 部分一致
  - それぞれの中で、選択中の県の駅 → 名前の短い順 → 県の順 → 駅 ID 順
  - 最大8件
  - 1文字から出す。空の入力では出さない
- **表示**
  - 各行は「候補・パネル用の名前」（太字、例「府中駅（東京都）」）と、右に小さく所在地（「東京都府中市」）
  - 選ぶと「富山駅 ×」の表示に変わる
- **候補が0件の時**
  - ひらがな・カタカナ（と「ー」）だけの入力:「漢字で入力すると候補が出ます」
  - それ以外:「候補がありません」（依頼に無い文言。何も出ないと入力が効いていないように見えるため足した）
- **iPhone のキーボードで気をつけた点**
  - 入力欄に触れて 0.3 秒後に、欄を画面の上端へスクロールする（見出し「最寄り駅」が見える位置）。候補がキーボードの上に並ぶようにするためです
    - 390×844 では、キーボードが出ても上の4〜5件は見える見込みです（`01-station-candidates.png`）
  - 候補のボタンは、押し始め（`mousedown`）で入力欄のフォーカスを外さない。候補を閉じるのは入力欄から離れて 0.2 秒後（工事5のタグ候補と同じ作り）
    - タップした瞬間に候補が消えて押せない、を防ぐため
  - 候補を選ぶと入力欄が「富山駅 ×」に変わる（入力欄が消える）ので、**キーボードは自然に閉じます**
    - 駅は1つしか選ばないので、続けて入力する必要が無いため
  - 入力欄・候補の文字は 16px（iOS の自動拡大を防ぐ）、候補の行の高さは 46px
  - Enter では送信しない
- 入力しただけで候補を選ばなかった文字は保存しません（駅は候補から選んだものだけ）

## 7. フォーム・店ページ・絞り込みの細かい決め事

- **県を変えた時**: 市を空にする（同じ県を選び直した時は残す）。駅は触らない
- **市の選択**
  - 先頭は「選択しない」
  - 県が未選択の間は押せない（薄い表示）
  - 候補にない値（見本データ等）は「選択しない」の次に残す（県の選択と同じやり方）
  - 県が空で市だけ入っている古いデータの時は、外せるよう押せるままにしました
- **自動補完**
  - 県が空なら駅の県を入れる
  - 市が空で、県が駅の県と同じなら駅の市を入れる
  - 入っている値は上書きしない（例: 県が石川県の時に富山駅を選ぶと、県は石川県・市は空のまま）
- **保存済みの駅 ID がマスタに無い時**
  - フォーム: 「（見つからない駅）×」
  - 店ページ: その行を出さない（ほかが空なら場所の欄ごと出さない）
- **絞り込み**
  - 市は「県＋市」の組で判定する。キーは `県名\t市名`（`cityKey`）。県なしの市（古いデータ）は県が空のキー
  - 駅は ID で判定する
  - どちらも「どれか」。ほかの種類とは「かつ」
- **候補**
  - 県を選んでいる時は、市・駅の候補をその県のものだけにする（選択中のものは0件でも残す）
  - 駅の県はマスタの県で判定する
  - 県・エリアの段は絞らない（依頼どおり）
- **市の候補名**: 同じ名前の市が候補に2つ以上ある時だけ「府中市（東京都）」
- **チップ**
  - 数える順番は 県 → 市 → 駅 → エリア（「富山県 ほか3」）
  - 市はチップでは市名だけ、駅は短い名前（「富山駅」）
- **場所パネルの「クリア」**: 県・市・駅・エリアをまとめて外す

## 12. 設計上の判断・迷った点

1. **北方領土の6村を除いた**（4.1）
   - 依頼の見込み 1,741件と合わせるためと、北海道の「泊村」の重複を避けるため

2. **グループの名前の決め方**（4.2）
   - 依頼は「まとめた中の最初の行（e_sort 順など）」でしたが、e_sort 順だと「魚津」→「新魚津」、「金沢」→「北鉄金沢」になるため、「代表の駅の行、無ければ一番短い名前」にしました
   - どちらも決定的です
3. **店ページの場所の欄を縦並びにした**
   - 工事4 では「県 市」と「エリア」を横に並べて折り返していました
   - 依頼 1-4 の「上から」に合わせて、1行ずつにしました（`shop.css` の1ルール）
4. **市の選択の「県が空で市だけある」場合**: 押せるままにしました。押せないと古いデータの市を外せないためです（通常の操作ではこの状態にならない）
5. **駅の候補の表示名**
   - 同じ県にも別の県にも同じ名前がある時（例: 白石＝札幌市に2駅＋宮城県）は、同じ県の方を優先して市を添えます
     - 札幌の2駅は「白石駅（札幌市）」
     - 宮城県の駅は「白石駅（宮城県）」
   - 市が無い駅で同じ県に同名がある時は県を添えます（今のデータには無い）
6. **並びの同順位**: 「名前の短い順 → 県の順」の次は駅 ID 順にしました（決定的にするため）
7. **絞り込みの市のキー**: 条件は `県名\t市名` の文字列で持ちます。条件の型が文字列の配列のままで済み、既存の付け外し関数 `toggleFilterValue` をそのまま使えるためです
8. **チップの市・駅の名前**
   - チップは幅が狭いので、市は市名だけ、駅は「富山駅」
   - パネルの中では、同名がある時だけ県・市を添えます
9. **候補が0件の時の「候補がありません」**: 依頼に無い文言ですが、何も出ないと入力が効いていないように見えるため足しました（不要なら消します）

   - 駅データ.jp の駅グループコードは、乗り換えできる近くの駅を1つにまとめています。そのため「1駅1件」にすると、代表以外の名前では候補に出ません
   - 富山県の例:「電鉄富山」「富山駅」（市電）→「富山」、「新魚津」→「魚津」、「高岡駅」（万葉線）→「高岡」、「宇奈月」→「宇奈月温泉」、「南富山駅前」→「南富山」
   - 大都市の例:「梅田」「大阪梅田」「北新地」「東梅田」→「大阪」、「三宮」「神戸三宮」→「三ノ宮」、「日比谷」→「有楽町」、「永田町」→「赤坂見附」、「なんば」→「大阪難波」、「名鉄名古屋」「近鉄名古屋」→「名古屋」、「明治神宮前〈原宿〉」→「原宿」
   - 例えば「梅田」と打つと、候補は0件です（「梅田」を含む別の駅名があればそれだけ）
   - 案: まとめた中の**ほかの名前も検索だけに使う**（選ぶと代表名「大阪駅」になる。店に持つ ID・件数は今と同じ）
     - マスタが1〜2割大きくなります
     - 選んだ時に「梅田」と打ったのに「大阪駅」になる違和感はあります
   - 依頼の範囲（持つもの＝ID・駅名・県・市）を超えるので、今回は入れていません。入れるかどうか決めてください
2. **駅の候補は漢字のみ**（無料版に読みが無い）。「とやま」は候補が出ず、案内が出ます（仕様どおり）
3. **ビルドの最初に読む JS が約 9 kB 増えました**（360.8 → 370.1 kB）
   - 候補・表示名などの関数とフォーム部品の分で、マスタ本体は別ファイルです
   - 駅名は最初の JS に入っていません（10章）
4. **同じ県・同じ市に同じ名前の駅が2つある組**（吹田・尼崎・西宮など、JR と私鉄）は、候補で見分けられません（4.5）
   - 無料版に路線名が無いためで、どちらを選んでも場所は同じです
5. **総務省の Excel の更新**: 生成スクリプトはファイル名 `000925835.xlsx` を決め打ちしています。新しい版にする時は実装役の工事になります（`data-src/README.md` に記載）
6. 登録画面の保存失敗時の診断表示（仮）は、引き続き残しています
