#### 1-1. 無圧縮 ZIP の読み書き（自作）
- 理由：全店のバックアップは写真が数百枚になり得る。JSZip は全部をメモリに展開するため iPhone でメモリが尽きる恐れがある。写真は JPEG 済みで圧縮しても小さくならない
- **書き出し**：各ファイルの中身（写真は DB の Blob）を**1つずつ**読んで CRC-32 を計算し、ローカルヘッダ・中身の Blob・セントラルディレクトリを並べて `new Blob([...])` で ZIP を組み立てる（中身の Blob はそのまま並べ、全部を1つの ArrayBuffer にしない）
  - 方式は STORE のみ。ZIP64・暗号化・データディスクリプタは使わない。ZIP の中のファイル名は ASCII だけ
  - 日時フィールドは書き出し日時（DOS 形式）でよい
- **読み込み**：`File`（Blob）の末尾から End of Central Directory を探し、セントラルディレクトリを読んで、必要なファイルだけ `blob.slice()` で取り出す。STORE 以外の項目・壊れた構造はエラー（アプリ用のエラー名。DOMException と同名は禁止＝3.7）
  - 写真を取り出す時は CRC-32 を確かめ、合わなければその写真は「読めない写真」として飛ばす
- `jszip` は `dependencies` から `devDependencies` へ移す（アプリからは使わない。テストで「自作の ZIP を JSZip が普通に読める」「JSZip が作った STORE の ZIP を自作の読み込みで読める」を確かめる用）。**新しい依存は足さない**
- Vitest で固定：往復（中身のバイト列一致）、空ファイル・0バイトの項目、日本語を含む JSON、CRC 不一致の検出、ZIP でないファイル、末尾が切れたファイル、上の JSZip との相互確認

#### 1-2. ファイル形式（仕様書 5章のとおり。形式バージョン 1）
- `manifest.json`：`format: "gourmet-card"`、`formatVersion: 1`、`kind: "share" | "backup"`、`exportedAt`、`appVersion`（工事8p の版の文字列。開発サーバーでは「開発版」でよい）、`shopCount`、`photoCount`
- `shops.json`（DB の店をそのまま。`undefined` の項目は書かない）、`tags.json`、`photos.json`（id・shopId・width・height・createdAt）、`photos/<写真id>-large.jpg`・`photos/<写真id>-small.jpg`
- 中身の読み取り・検証は純粋関数に。検証で見るもの：
  - `format` が違う・`manifest.json` が無い → 「グルメカードのファイルではありません」
  - `formatVersion` が今より新しい → 「新しい版のアプリで作られたファイルです。アプリを新しくしてから取り込んでください」（取り込まない）
  - 店ごとに：店名（空白を除いて空でない）、status・origin は決まった値、rating は 1〜50 の整数か無し、写真は3枚まで、タグ id の配列、日時は ISO 文字列に正規化（3.7）。**おかしい店はその店だけ飛ばし**、件数を数える（全体は止めない）
  - 写真の実体が無い・CRC 不一致 → その写真だけ外す（店は入れる）
- 既存の `src/db/shops.ts` の検証関数を使いたい場合は、**export を足すだけ**の最小変更は可（中身は変えない）

#### 1-3. 書き出し
- **1店（`kind: share`）**：その店・その店の写真（大小）・その店に付いているタグだけ
- **全店（`kind: backup`）**：手札・行きたいの全店、全写真、**全タグ（どの店にも付いていないタグも）**。設定はファイルに入れない
- 写真は1枚ずつ読んで ZIP に並べる（1-1）。準備中は進み具合を出す（例「準備しています… 写真 12/60」）
- ファイル名（日本時間）：1店 `グルメカード_<店名>.gcard`（店名のうちファイル名に使えない文字 `\ / : * ? " < > |` と改行は `_`、長すぎる時は 40 文字程度で切る）／全店 `グルメカード_バックアップ_YYYYMMDD-HHmm.gcard`
- 拡張子と MIME は**1か所の定数**にまとめ、試験用の切替（1-6）で次の2つを選べるようにする（工事8aで1つに固定する時に1か所の変更で済むように）
  - `.gcard`：MIME `application/octet-stream`（既定）
  - `.zip`：MIME `application/zip`

#### 1-4. 共有とダウンロード（2段階）
- 送る・バックアップのボタンを押したら、下から出るシート（工事6の `BottomSheet` を使ってよい）で「準備しています…」→ できたら「準備できました（1.8MB）」と大きさを出し、
  - **主ボタン「共有メニューを開く」**：`navigator.canShare({ files: [file] })` が true の時だけ出す。押したら `navigator.share({ files: [file] })`（title・text は付けない）
  - **控えめなボタン「ファイルとして保存」**：常に出す。`<a download>`＋object URL でダウンロード（押した操作の中で実行）
- **準備の処理と `navigator.share` を同じ押下の中で続けて呼ばない**（iPhone の Safari は時間のかかる処理のあとでは共有を許さないため。必ず2回目の押下で呼ぶ）
- 共有が完了（`share()` が成功）→「送りました」等を出して閉じる。`AbortError`（共有メニューを閉じた）→ 何も言わずシートに戻る。その他のエラー → 短い文言＋エラー名を小さく出し、「ファイルとして保存」を案内
- **最後のバックアップ日時**：全店の書き出しで、共有が成功した時・「ファイルとして保存」を押した時に `settings.lastBackupAt` を記録（1店を送った時は記録しない）
- object URL は使い終わったら解放する

#### 1-5. 取り込み（下見 → 確認 → 保存）
- 「ファイルから取り込む」→ 隠した `<input type="file">` を `click()`。**`accept` 属性は付けない**（iPhone は知らない拡張子を `accept` で指定すると選べなくなることがあるため）
- 選んだファイルを下見して**確認画面**（シートでも画面内でもよい）を出す：
  - 種類：「お裾分け（友人から）」／「バックアップ（自分の端末の復元用）」、書き出し日時
  - 「新しいお店 3件」「もう入っているお店 1件」（同じ `id` があるか）、飛ばす店・写真があればその件数
  - もう入っている店が1件以上ある時だけ、「もう入っているお店は：● 取り込まない（既定）／○ 上書きする」
  - お裾分けの時は「『行きたい』として取り込みます」と一言
  - 取り込む店が0件（全部もう入っていて「取り込まない」等）なら取り込むボタンは押せない
- 「取り込む」で保存（進み具合を出す）→ 結果「3件取り込みました（1件はもう入っているため取り込みませんでした）」。取り込んだのが1店ならその店ページへ行くボタン、複数なら一覧へ（お裾分けは「行きたい」タブ、バックアップは「手札」タブを開けるとよい。難しければ一覧でよい。どうしたか報告）
- **取り込み専用の保存関数**（`createShop` は自分登録専用のまま変えない＝3.7）：
  - 1店ずつ Dexie のトランザクション（shops・photos・tags を含める＝3.8）で保存。途中で失敗しても、それまでに入った店は壊れない。失敗した店は件数に出す
  - **お裾分け（share）**：`status: 'wishlist'`、`origin: 'shared'`、`createdAt`・`updatedAt` は取り込んだ日時。id・名前・評価・メモ・場所・URL・写真・タグはそのまま
  - **バックアップ（backup）**：id・日時・status・origin を含め**全部そのまま**
  - **上書き**：その店を届いた内容（share なら上の変換後）で置き換え、その店の今の写真を全部消して届いた写真に入れ替える
  - 写真：ファイルの id・width・height・createdAt を保つ。取り出した Blob は `type: 'image/jpeg'` の Blob として保存（ファイルの切り出しのままでなく、1枚ずつ読んだバイト列から作る）。万一 id が別の店の写真と重なる時は新しい id を振る
  - タグ：同じ種別＋正規化キーのタグが端末にあればそれに合流（端末の表示名のまま）。無ければ作る（バックアップ・お裾分けとも、ファイルの id が端末で空いていれば id・作成日時を保つ。空いていなければ新しい id）。店のタグ id は付け替える。バックアップの「どの店にも付いていないタグ」も同じ規則で入れる
  - 駅 id が駅マスタに無くても、そのまま保存してよい（店ページは出さないだけ＝工事7）
- 取り込み後、一覧・タグ候補・絞り込みの候補が新しい店を含むこと（一覧のモジュール変数の記憶が古いまま出ないように）

#### 1-7. テスト
- **Vitest（最重要）往復テスト**：見本的なデータ（手札・行きたい、評価あり／なし、県・市・駅・エリア・ジャンル・使い道・URL・メモの有無が混ざった店、写真0〜3枚、どの店にも付いていないタグ）を DB に入れ → 全店書き出し → **空の DB** に取り込み → 店・写真（大小のバイト列・width・height・createdAt）・タグ・日時・status・origin・写真の順（`photoIds`）が**すべて一致**すること。項目が無い（undefined）ことも一致させる
- お裾分け：1店を書き出し → 別の空の DB に取り込み → wishlist・shared・日時は取り込み時刻（テストの時計で固定）、他は一致
- 同じ id：既定（取り込まない）で端末の店が変わらない／上書きで置き換わり、古い写真が消える
- タグの合流（全角・大文字違いの既存タグに合流）、id の重なり
- おかしいファイル：ZIP でない／manifest 無し／新しい formatVersion／おかしい店だけ飛ばす／写真の CRC 不一致
- ファイル名の整え方、日本時間の日付
- **Playwright（スマホ幅、Chromium）**：
  - 店ページ「この店を送る」→ 準備 →「ファイルとして保存」でダウンロードされる → **新しいブラウザコンテキスト**（空の端末）で「バックアップと取り込み」→ そのファイルを選ぶ → 確認に「新しいお店 1件」「お裾分け」→ 取り込む → 行きたいに出て、店ページに「もらったお店」、写真が表示される

  - 共有メニューの経路：`addInitScript` で `navigator.canShare`／`navigator.share` を差し替え、「共有メニューを開く」が出て、`share` に `.gcard` の File が1つ渡ること、準備と同じ押下では呼ばれないこと。canShare が無い時はボタンが出ないこと
  - 試験用の切替を `.zip` にすると、ファイル名が `.zip` になること。`.zip` のファイルも取り込めること
- `e2e:dist`：一覧のメニューから「バックアップと取り込み」が開ける確認を1つ足す
