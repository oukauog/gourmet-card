#### 1-2. 登録・編集の共通フォーム（新規ファイルで作る）

#### 1-3. 写真（追加・削除・並べ替え）
- 今の `PhotoPicker` の動き（最大3枚、1枚ずつ処理、失敗した写真は枠にメッセージ、4枚目は「写真は3枚までです」、`capture` 属性なし）は変えない
- 各写真に「◀」「▶」の小さなボタンを足し、左右に入れ替えられるようにする（先頭の「◀」・末尾の「▶」は出さないか押せなくする）。**先頭が表紙**で、「表紙」ラベルは先頭の保存対象の写真に付く（今と同じ考え方）。ボタンは `aria-label`（例「写真2を左へ」）を付ける
- 登録画面でも同じく並べ替えられる
- 編集画面では、保存済みの写真（`small` を表示）と新しく足した写真が同じ列に並ぶ。削除（×）・並べ替え・追加は**画面上だけで行い、保存を押した時にまとめて DB に反映**する（キャンセルすれば元のまま）
- `usePhotoDrafts` を広げるか、新しいフックで包むかは任せる。広げる場合は既存の動き（登録画面の e2e）を壊さないこと

#### 1-4. 評価入力（スライダー＋±0.1）
- 大きめの数値表示（例「3.7」）と、その横に既存の `Stars` 部品（比例塗り）を並べ、値に合わせてその場で動かす
- その下に横スライダー（`<input type="range" min=1 max=50 step=1>`、内部値は 1〜50 の整数）と、左右に「−0.1」「＋0.1」ボタン（1〜50 の範囲で止める）
- **未評価の状態を持つ**：未評価のときは数値の代わりに「未評価」と表示し、スライダーは薄く表示。スライダーに触れる／± を押すと評価が付く（未評価から ± を押した時の起点は 3.0）。評価があるときは小さな「未評価に戻す」ボタンを出す
- 保存するのは整数 1〜50 か未設定だけ（`ratingFromNumber` は使わなくてよい。0.1 刻みでない値が入る経路を作らない）
- スライダーは画面の左右端から少し離す（iPhone の戻るスワイプとぶつからないように）
- 値の増減・範囲の丸め・未評価からの起点は `src/lib/` の**新規ファイル**の純粋関数にして Vitest で恒久テスト

#### 1-5. タグ入力（ジャンル・エリア・使い道）
- **ジャンル・エリア**：付けたタグをチップ（× で外す）で並べ、その後ろに文字入力欄
  - 入力中は `suggestTags(kind, 入力文字, 8)` の候補を出し（付け済みのものは除く）、タップで追加
  - **欄に触れただけ（空欄）でも既存タグを候補に出す**（新規作成より選ぶ方が楽な画面。3.4）
  - Enter か「追加」で入力文字をそのまま追加。正規化キー（`normalizeTagKey`）が既存タグと一致すればその既存タグを使う（表示も既存の表記）。同じフォーム内での重複は正規化キーで防ぐ
  - **新しいタグは保存を押した時に作る**（キャンセルで孤立タグが増えないように。入力途中の段階で `findOrCreateTag` を呼ばない）
- **使い道**：既存の use タグを全部チップで並べ、タップで付け外し。末尾に小さな「＋追加」→ 入力欄が出て新しい使い道を足せる（作るのは保存時、上と同じ）
- タグの並びは付けた順（`genreTagIds` 等の順）で保存

#### 1-6. 保存処理（新規ファイル。`src/db/` に置いてよい）
- **新規登録**：店＋写真＋新しいタグを1トランザクションで保存。今の `createShopWithPhotos` は変更せず、新しい関数から呼ぶか同じ考え方で組む
- **編集**：次を1トランザクションで行う新しい関数（例 `saveShopEdit`）
  - 新しいタグを作る（`findOrCreateTag`）→ `updateShop` で項目を更新 → 消した写真を `removePhoto` → 足した写真を `addPhoto` → 最終の並びで `reorderPhotos`
  - **途中で失敗したら何も変わらないこと**（例：写真が上限を超える・店が消えていた）。これをテストで固定
- 使うのは工事1の公開 API だけ。**Dexie の親トランザクションは子 API が触る全テーブル（shops・photos・tags、必要なら settings）を含める**（欠けると `SubTransactionError`。工事2の教訓）
- `updateShop` に渡すのは変わった項目だけでなく全部でもよいが、**`city` と `stationId` は 1-2 のルールどおり**（県を変えた時だけ `city` を未設定に、`stationId` は渡さない）
- fake-indexeddb で単体テスト（新規登録で全項目が保存される／編集で並べ替え・削除・追加が一度に反映される／失敗時に元のまま／新しいタグは保存時にだけ作られる）

#### 1-7. 使い道の初期タグ（「個室あり」「駐車場あり」）

- 設定キーの追加は仕様書 3.6 のとおり `types.ts` の `SettingsMap` と `settings.ts` の検証の両方に足す（**`src/db/` の既存ファイルの変更はこの2か所だけ**。最小に）

- **花井さんの iPhone 実機確認手順**（次の内容を短く）
  1. `npm run dev` → iPhone で `Network:` の URL を開き再読み込み
  2. 新規登録：写真＋店名だけで保存 → 店ページが開く。もう1件、評価・タグ・県・エリア・URL・メモ・「行きたい」まで入れて保存
  3. 評価の入れやすさ：スライダーで大まかに合わせ、±0.1 で狙った値（例 3.7）にできるか。スライダーを触る時に戻るスワイプやページのスクロールが誤作動しないか

  5. 編集：写真の ◀▶ で表紙を変えて保存 → 店ページと一覧の表紙が変わる。編集してキャンセル → 元のまま
  6. 「行きたい」の店で「行った！」→ 編集画面が開く → 写真と評価を足して保存 → 手札の店になっている
