#### 1-2. manifest と Service Worker（仕様書 4.6「作り」）
- `vite.config.ts` に `vite-plugin-pwa` を足す
  - Service Worker は**ビルドした版だけ**（開発サーバーと e2e では登録しない。`devOptions` は無効のまま）
  - 方式は generateSW、更新は **prompt 方式**（自動で読み直さない）。登録は 1-3 のフックから行い、自動の登録スクリプトは入れない
  - manifest：`name`・`short_name` は「グルメカード」、`lang: ja`、`start_url` と `scope` は公開の base（`/gourmet-card/`）に合わせる、`display: standalone`、`background_color`・`theme_color` は今のアプリの地の色、アイコンは 1-1 の PNG（maskable を含む）。画面の向きは指定しない
  - 事前キャッシュ：アプリ本体・CSS・`index.html`・アイコン・manifest、**駅と市区町村のマスタの別ファイル（工事7）も含める**。どのファイルが入ったかと合計の大きさを報告に書く。ほかのサイト（Googleマップ等）は一切キャッシュしない
  - 古いキャッシュは片付ける設定にする
- `index.html`：`apple-touch-icon`、`apple-mobile-web-app-title`（グルメカード）、`apple-mobile-web-app-capable`・`mobile-web-app-capable`、`apple-mobile-web-app-status-bar-style` は `default`（白地に黒字）、`theme-color`
- ホーム画面から開いた時（全画面）に、一覧の上部バーと店ページの浮いた「戻る」が iPhone の上端（時計の所）に重ならないよう、`env(safe-area-inset-top)` の余白を足す（ブラウザでは 0 なので見た目は変わらない）。足す CSS は新しいファイル（例 `src/styles/pwa.css`）に置く
- iPhone のホーム画面アプリでは、画面の端からの戻るスワイプが効かない可能性がある。一覧以外の画面（登録・編集・店ページ・バックアップと取り込み）に、画面の中の戻る／キャンセルがあることを確かめて報告に書く（無い画面があれば足さずに報告）
- `scripts/deploy.mjs` で `sw.js`・`workbox-*.js`・`manifest.webmanifest` が `gh-pages` に載ることを確かめる（変更が要らなければ触らない）

#### 1-3. 更新の帯（仕様書 4.6。花井さん決定：帯を出して押すと更新）
- `vite-plugin-pwa` のフック（`virtual:pwa-register/react` 等）を包む小さな部品を新しいファイルに置く（例 `src/pwa/`）。開発サーバー・e2e では何もしない
- 新しい版を取りに行くのは、アプリを開いた時と、**アプリに戻ってきた時**（`visibilitychange` で見えるようになった時。1分に1回まで）。iPhone のホーム画面アプリは完全に閉じないことが多いため
- 新しい版が揃ったら「新しい版があります［更新］」の帯。押すと新しい版で読み直す。**勝手に読み直さない**
- 帯を出すのは一覧と「バックアップと取り込み」画面だけ（登録・編集の途中には出さない）
- 確認のため、DEV の時だけ「新しい版がある」状態を作れる差し替え口を用意してよい（本番のビルドに含めない）
- 版の表示を「バックアップと取り込み」画面の最下部にも出す（フォームの最下部の表示はそのまま）

#### 1-4. persist と保存の状態（仕様書 4.6）
- 起動時、店が1件以上あり、`navigator.storage.persisted()` が false なら `navigator.storage.persist()` を1回求める。無い・失敗した時は何も出さない
- 「バックアップと取り込み」画面に「この端末での保存」の欄を足す
  - 「保護されています」／「保護されていません」（API が無い時は出さない）
  - 使用量の目安（`navigator.storage.estimate()` の `usage`。「約 42MB」の形）
  - 「**ホーム画面で使う**」の説明（いつも出す）：iPhone／Android の追加の手順、「Safari 等で入れたお店はホーム画面のアプリには出ません。バックアップして、ホーム画面のアプリで取り込んでください」、「ホーム画面のアイコンを削除すると、そのアプリのお店も消えます。先にバックアップしてください」

#### 1-5. バックアップの促しとホーム画面追加の案内（仕様書 4.6）
- 判定は純粋関数にして `src/lib/` に置き、Vitest で固定する（例 `banners.ts`）
  - **バックアップの促し**：店が1件以上、かつ基準日から **30日以上**。基準日は `lastBackupAt`、無ければ `firstShopAt`。どちらも無ければ出さない。× を押した日時（`backupReminderDismissedAt`）から **7日未満**なら出さない。日数は経過時間 ÷ 24時間の切り捨て
  - `firstShopAt`：一覧を表示した時に店が1件以上あり、まだ無ければその時刻を記録する（保存・取り込みの関数は触らない）
  - **ホーム画面追加の案内**：ホーム画面から開いていない（`display-mode: standalone` でなく、`navigator.standalone` も true でない）スマホのブラウザだけ。iPhone・iPad（`Macintosh` で `maxTouchPoints > 1` も iPad とみなす）は iPhone の手順、Android は Android の手順、それ以外（PC）は出さない。× を押したら（`installGuideDismissedAt`）以後出さない
  - **帯は同時に1本まで**。優先は 更新 → ホーム画面追加 → バックアップの促し。選択モード（工事8b）の間はどれも出さない
- 設定キー3つ（`firstShopAt`・`backupReminderDismissedAt`・`installGuideDismissedAt`、どれも ISO 文字列）を `types.ts` の `SettingsMap` と `settings.ts` の検証に足す（既存キーの扱いは変えない）
- 帯の見た目：一覧の上部バーとタブの間に、細く控えめに（淡い地・小さめの文字・右端に ×）。写真の一覧を大きく押し下げない
  - 促し：「最後のバックアップから32日たちました」（一度もしていない時は「まだバックアップしていません」）＋「バックアップする」→ `#/data`
  - 案内：「ホーム画面に追加するとアプリとして使えます」→ 押すと工事6の `BottomSheet` で手順のパネル
    - iPhone：① 画面下の共有ボタン ②「ホーム画面に追加」③ ホーム画面のアイコンから開く
    - Android：① 右上のメニュー ②「ホーム画面に追加」または「アプリをインストール」③ ホーム画面のアイコンから開く
    - 店が1件以上ある時だけ、移し方の注意（1-4 と同じ文）と「バックアップと取り込みへ」ボタン
- B-3：帯とパネルは新しいファイル（例 `src/components/banner/`）。`HomeScreen.tsx`・`DataScreen.tsx`・`App.tsx` の変更は呼び出しの追加だけに

#### 1-6. テスト
- 単体（Vitest）：1-5 の判定の境目（29日／30日、× から6日／7日、`lastBackupAt` と `firstShopAt` の優先、0件、端末の判定（iPhone・iPad・Mac の iPad・Android・PC・standalone）、帯の優先）
