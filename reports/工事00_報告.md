## 8. 仕様書 2.1 のスタックへの意見（変更はしていない）

基本構成（Vite + TS + React / Dexie / vite-plugin-pwa / ZIP / Vitest / Playwright）は**このままで問題ない**と判断します。静的ファイルだけで動き、GitHub Pages に載ります。以下は補足・将来の注意点です。

1. **Lint が ESLint ではなく oxlint**: 最新の Vite テンプレートは ESLint ではなく oxlint を同梱するようになっていました。依頼文の「テンプレート同梱のもので可」に従い oxlint を採用（`npm run lint`）。機能上の差は当面問題なし。
2. **Playwright に WebKit（Safari 系）を追加する提案**: 主端末が iPhone なので、Chromium だけでは Safari 特有の問題（IndexedDB・ファイル共有・写真取り込み）を拾えません。Windows 版 Playwright の WebKit は iOS Safari と完全に同じではないものの、目安にはなります。工事2（写真）・工事8（書き出し）あたりで追加を検討したいです。最終判定は実機（C-4）。
3. **Dexie のユニットテスト**: Vitest（Node 環境）には IndexedDB が無いため、工事1で `fake-indexeddb`（テスト専用）の追加が必要になる見込みです。
4. **JSZip**: 動作は問題ありませんが更新頻度が低めです。写真の多い全店バックアップで iPhone のメモリが厳しい場合、より軽量な `fflate` が代替候補。工事8の往復テスト・実機確認で判断すればよく、今は JSZip のままで良いと考えます。
5. **HEIC**: iPhone の Safari は `<input type="file">` で写真を選ぶと通常 JPEG に変換して渡しますが、ファイルアプリ経由などで HEIC のまま来る場合もあります。工事2で実機確認が必要（仕様書 3.3 の「要実機確認」のとおり）。
6. **GitHub Pages の base**: 工事9で `vite.config.ts` に `base: '/gourmet-card/'` が必要（仕様書 2.2 のとおり）。
