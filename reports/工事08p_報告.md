## 5. `npm run deploy` の中身

```
npm run build && node scripts/deploy.mjs
```

- **ビルド**（`tsc -b && vite build`）が失敗すると、`&&` で止まり公開しない
- **`scripts/deploy.mjs`**
  - `dist/index.html` が無ければ止まる
  - 足した devDependency `gh-pages` の API で、`dist/` を origin の `gh-pages` ブランチへ push する
    - ブランチの中身はビルド結果だけで、毎回すべて入れ替える
    - コミットメッセージは `Deploy <短いハッシュ>`
  - 失敗した時（認証など）は `ERROR: publish failed: …` を出して止まる（回避はしない）
  - 作業ツリーに変更がある時は `WARNING` を出す（公開は止めない。版に `+` が付く）
- **devDependency `gh-pages`（6.3.0、MIT）を選んだ理由**
  - `dist/` を別ブランチへ push するための定番のパッケージ
  - 一時的な clone（`node_modules/.cache/gh-pages`）の中で作業するので、作業ツリーや `main`・作業ブランチを一切触らない
  - `npm install` 時の脆弱性報告は 0件
- **`.nojekyll` の入れ方**: `gh-pages` の `nojekyll: true` で公開の度に作る（公開 URL の `/.nojekyll` が 200）
- `dist/` は今までどおり `.gitignore` で、`main`・作業ブランチにビルド結果はコミットしていない

### 途中で直したこと（1回目の公開の後）
- 1回目は `gh-pages` のコマンド（`gh-pages -d dist --nojekyll`）で公開した。すると、公開ブランチに `main` のドットファイル（`.gitattributes`・`.gitignore`・`.oxlintrc.json`・`reports/.gitkeep`）が紛れ込んだ
  - 原因は2つ
    - `gh-pages` は最初に clone した `main` の中身から公開ブランチを作る
    - 古いファイルの掃除にドットファイルを含めない（`--dotfiles` を付けても掃除には効かない。ソースで確認）
  - 秘密の情報ではないが、公開ブランチはビルド結果だけのはずなので、公開処理を Node スクリプトに替えた。掃除の対象にドットファイル（`**/.*`）を明示している

## 6. 版の埋め込み方

- `vite.config.ts` の中で、ビルドの時だけ次を計算し、`define` で `__APP_BUILD__` として JS に埋め込む
  - **ハッシュ**: `git rev-parse --short HEAD`
  - **`+`**: `git status --porcelain` が空でなければ後ろに付ける（未追跡のファイルも「変更あり」に数える）
  - **git が無い・失敗した時**: 例外を握りつぶして `unknown` にする。ビルドは失敗しない
  - **ビルド日時**: ISO 形式の UTC で埋め込み、画面で日本時間の `YYYY-MM-DD HH:mm` にする（`formatJst`。UTC+9 を足すだけで、端末の時刻設定に左右されない）
- **開発サーバー**: `__APP_BUILD__` が `undefined` になり、画面は「開発版」
- **表示**: `VersionLine` が `versionText()` の結果を出す
  - 出典表記と同じ小さな灰色の文字（11px）
  - 例: `版 45fa0a5（2026-09-27 17:47）`
- **型**: `src/buildInfo.d.ts` で宣言した。`tsc -b --noEmit` は合格
  - 念のため、画面側は `typeof __APP_BUILD__ === 'undefined'` で確かめてから使う

## 10. 設計上の判断・迷った点

1. **公開処理を Node スクリプトにした**（5章）
   - `gh-pages` のコマンドのままでは、公開ブランチに古いドットファイルが残るため
   - 依存は `gh-pages` の1つのままです
2. **`e2e:dist` は毎回ビルドする**（`reuseExistingServer: false`）
   - `npm run deploy` で公開されるものと同じものを確かめるため
   - 1回 7 秒ほどです
3. **公開版の e2e のフォルダは `e2e-dist/`** にした
   - 既存の設定（`testDir: './e2e'`）に拾われないよう、既存の設定を変えずに分けるため
   - 型チェックのため `tsconfig.node.json` の `include` に足した
4. **「未追跡のファイル」も `+` に数える**
   - 新しいファイルをコミットし忘れたままのビルドも見分けるため
   - `.gitignore` の対象（`dist/` や `test-results/`）は数えません
5. **開発サーバーの表示は「開発版」**（「版」は付けない）。依頼の例に合わせました
6. **公開ブランチの履歴は残る形**（`gh-pages` の既定）。毎回コミットが1つ増えます。消したい場合は変えられます
