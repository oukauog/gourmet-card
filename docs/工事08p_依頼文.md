目的：次の工事8（書き出し・取り込み・共有）で使う Web Share API などは **https でないと動かない**ため、iPhone の実機確認を本番と同じ `https://oukauog.github.io/gourmet-card/` で行えるようにします（工事9の「公開」だけを前倒し。PWA 化は工事9のまま）。

まず次を読んでから着手してください。
- `CLAUDE.md`
- `docs/01_仕様書.md`（**v0.12**。特に 2.1、**2.2 公開先（先行公開）**、**2.4 リポジトリ運用**、7章 工事計画の 8p・9）

花井さんと相談役で決めたこと（仕様書 2.2 と同じ）：
- 公開は **`npm run deploy`** で、ビルド結果を **`gh-pages` ブランチ**へ push する方式（GitHub の Pages 設定は「Deploy from a branch：`gh-pages` / (root)」）

### 環境の注意（日本語Windows）
- バッチファイル（.bat / .cmd）は作らない・使わない。スクリプトは npm scripts / Node / Python で書く
- コンソール出力は文字化けを避けるため英数字中心にする。ファイルは UTF-8（BOMなし）で読み書きする
- パスに日本語・空白が含まれる前提でクォートする
- 既存ファイルの編集は B-1 に従い、スクリプト経由の決定的な手段で行う（これまでと同じ流儀。置換元が1か所だけであることを確かめ、合わなければ何も書かずに止まる）

### 1. やること

#### 1-1. ビルド時だけ `base: '/gourmet-card/'`
- `vite.config.ts` を最小の変更で、**ビルド（と `vite preview`）の時だけ** `base` を `/gourmet-card/` にする。開発サーバー（`npm run dev`）は `/` のまま（iPhone の LAN 確認・既存 e2e をそのまま使うため）
- `dist/index.html` が読む JS・CSS・ファビコンがすべて `/gourmet-card/` で始まっていることを確かめる
- 駅・市区町村マスタの別ファイル（工事7。`import()` で読むもの）も `/gourmet-card/assets/…` から読めること
- `src/` と `index.html` に `/` で始まる URL の直書き（`fetch('/…')`、`<img src="/…">` 等）が無いか grep し、結果を報告（あれば `base` に追従する形に直してよい。直した箇所は報告）
- ルーターはハッシュ方式なので `404.html` 等の対策は作らない

#### 1-2. 公開コマンド `npm run deploy`
- devDependency を**1つだけ**足してよい（例：`gh-pages`。選んだものと理由を報告）
- `npm run deploy` の中身：**本番ビルド（`npm run build`）→ 成功した時だけ `dist/` を origin の `gh-pages` ブランチへ push**。ビルドが失敗したら公開しない
- 公開物に `.nojekyll` を含める（GitHub Pages の Jekyll 処理で `_` で始まるファイルが消える事故を防ぐ。含め方は任せる）
- `gh-pages` ブランチは公開専用（ビルド結果だけ。毎回上書きされる）。`main` や作業ブランチにはビルド結果をコミットしない（`dist/` は今までどおり `.gitignore`）
- push に失敗した時（認証など）は、無理に回避せず止めて報告

#### 1-3. 版の表示
- ビルド時に「コミットの短いハッシュ」と「ビルド日時（日本時間 `YYYY-MM-DD HH:mm`）」をアプリに埋め込む（Vite の `define` 等。方法は任せる）
  - 未コミットの変更がある状態でビルドした時は、ハッシュの後ろに `+` を付ける（例 `d844c4f+`）
  - git が使えない環境でもビルドを失敗させない（その時は `unknown`）
  - 開発サーバーでは「開発版」と出す
- 表示場所：**登録・編集フォームの最下部、出典表記の下**に、出典と同じ小さな灰色の文字で1行
  - 例：`版 d844c4f（2026-09-27 21:05）`
- 型の宣言を足す場合は既存の型チェックが通るように（`tsc -b --noEmit`）
- 版の文字列を組み立てる純粋関数を作る場合は Vitest で固定する（作らない場合は不要）

#### 1-4. 公開版の確認用 e2e（新規）
- ビルド結果を `vite preview` で `/gourmet-card/` として開き、Playwright（スマホ幅 390×844、Chromium）で確かめる仕組みを**既存の e2e とは別に**足す
  - 別の設定ファイル（例 `playwright.dist.config.ts`）＋ npm script `e2e:dist`。ポートは 5173 と重ならないものにする（既存の `npm run e2e` とは同時に動かさない前提でよい）
  - 最低限の確認：
    - `/gourmet-card/` を開くと一覧が出る（コンソールにエラーが無い、404 の読み込みが無い）
    - 「＋」から登録画面 → 写真なしで店名だけ保存 → 店ページ → 再読み込みしても残る
    - フォームの最寄り駅に「富山」と入れると候補に富山駅が出る（駅マスタの別ファイルが `/gourmet-card/` の下から読める）
    - フォーム最下部に `版 ` で始まる表示があり、「開発版」ではない
    - 見本データのボタンが無い
- 既存の `npm run e2e`（開発サーバー相手）は変えない。全部そのまま通ること

#### 1-5. 公開する
- 1-1〜1-4 がすべて通り、`work/08p-pages` にコミット・push してから `npm run deploy` を実行する（作業ツリーがクリーンな状態で。版に `+` が付かないように）
- GitHub の Pages 設定：
  - `gh`（GitHub CLI）が入っていて認証済みなら、Pages の状態を調べ、未設定なら「`gh-pages` ブランチ / (root)」で有効にしてよい（使ったコマンドを報告）
  - `gh` が無い・認証されていない時は、設定しないで報告に**花井さん向けの設定手順**（画面の名前どおり、短く）を書く
- 公開 URL `https://oukauog.github.io/gourmet-card/` が見られる状態なら、`curl` 等で次を確かめて報告（見られない時は「Pages 設定待ち」と書く）
  - `index.html` が 200、中の JS・CSS が 200、駅マスタの別ファイルが 200
  - 返ってきた JS の中に、今回のコミットの短いハッシュが入っている
