## 4. 店ページの作り

- **読み込み**: `getShop` → `getPhotosForShop` と `listTags()` を同時に読む
  - 写真は **`shop.photoIds` の順**に並べ直し、**`large` だけ**を使う（`small` は使わない）
  - タグは ID から引き、存在しない ID は黙って飛ばす
- **読み込み中は何も出さない**（戻るバーも出さない）。IndexedDB からなので一瞬です。店が無い時は今までどおり「この店は見つかりません」と「一覧へ戻る」
- ページを開いたら先頭へスクロール（今までと同じ）。再読み込み・戻る・一覧のスクロール位置の復元は、ルーターと `HomeScreen` に手を入れていないので工事3のまま（既存の e2e も全部通過）
- **店名**: 24px・太字。長い店名は折り返す（`overflow-wrap: anywhere`）
- **☆**: 既存の `Stars` を 22px で使用。未評価は灰色の「未評価」
- **タグ**: ジャンル → 使い道の順に、それぞれ店の `genreTagIds` / `useTagIds` の順で小さなチップで並べる
  - ジャンルは淡い灰色の塗り、使い道は枠線だけ（灰色の文字）で区別
  - 見出しは付けていない（チップだけで分かるため）
- **場所**: 小さな見出し「場所」の下に「富山県 富山市」、続けて灰色で「総曲輪・八尾」。県・市・エリアのどれも無ければ見出しごと出さない。最寄り駅は出していない（工事7）
- **Googleマップで開く**: `isOpenableUrl(mapUrl)` が true の時だけ、`<a href target="_blank" rel="noopener noreferrer">`（前後の空白を除いた URL）。幅いっぱいのボタンで、ピンのアイコン付き
- **メモ**: 小さな見出し「メモ」の下に、`white-space: pre-wrap` と `overflow-wrap: anywhere` で表示。URL の自動リンクはしない
- **この店を削除**: 最下部の中央に、赤い文字だけの控えめなボタン（14px）。文字と動き（確認 → 削除 → `onDeleted`）は同じ

## 5. 写真スワイプの作り

- **scroll-snap の設定**（`carousel.css`）
  - 横スクロールの枠: `display: flex`、`overflow-x: auto`、`scroll-snap-type: x mandatory`、`overscroll-behavior-x: contain`、スクロールバーは非表示（`scrollbar-width: none` と `::-webkit-scrollbar`）
  - 各スライド: `flex: 0 0 100%`（画面幅いっぱい）、`scroll-snap-align: start`、`scroll-snap-stop: always`（勢いよく払っても1枚ずつ止まる）
  - 写真: `object-fit: cover` で枠に合わせて切り抜く
  - 枠の高さは `aspect-ratio: var(--photo-ratio, 1)` で、店ページのクラスが `--photo-ratio` を決める（1:1 は `1`、4:5 は `4 / 5`）
  - タッチイベントは一切処理していない（慣性はブラウザ任せ）
- **位置の計算**: スクロールの `onScroll` で `slideIndexFromScroll(scrollLeft, clientWidth, 枚数)` を呼び、四捨五入で一番近い1枚を求める。結果は 0〜枚数−1 に収まり、幅0・枚数0 でも例外にしない。1枚の時は `onScroll` を付けない
- **点**: 2枚以上の時だけ、写真の下端中央に重ねる。白 50%・影つき、今の1枚だけ白 100%。表示だけで、タップしても何も起きない（`pointer-events: none`）
- **写真なし**: 高さ 100px の帯。色は一覧の写真なしタイルと同じ `tileToneIndex(店名)` の6色
  - 色の定義は `home.css` を触らないため、`carousel.css` に同じ値を複製した（工事4a か工事10で1か所にまとめたい）
- **写真のタップ**: 何も起きない（拡大は作っていない）
- **代替テキスト**: 1枚なら店名、複数なら「店名 写真1/3」のように番号付き

### 戻るスワイプとの関係で気づいたこと
- 写真は画面の左右端まであるため、iPhone で画面の左端から右へ払うと、指は写真の上から動き始めます
- iOS Safari の「左端からの戻る」はブラウザ側の操作で、ページ内の横スクロールより先に処理されるのが普通です。ただし、端のどこまでが「戻る」になるかは機種や iOS の版で違うので、**実機で確かめてください**（9章 手順2）
- `overscroll-behavior-x: contain` を付けたので、1枚目で右へ（または最後の写真で左へ）払いすぎても、その勢いがページやブラウザに伝わりません。例えば Android の Chrome で、写真の上の横払いが「前のページに戻る」に化けることを防ぎます
- PC の e2e（Chromium）では、スクロール位置を変えると点が切り替わることと、scroll-snap の設定が入っていることまで確認しています。**指の操作の感じ（1枚ずつ止まるか・引っかからないか）は実機でしか確かめられません**

## 7. 見本データの拡張（`src/dev/sampleData.ts`。開発時のみ）

- i 番目の見本の店の項目は、関数 `sampleFields(i)` が i だけから決める（乱数は評価だけ。今までどおり7件に1件は未評価）

| 項目 | 決め方 |
|---|---|
| ジャンル | `i % 4` が 0 → 2個、1 → 1個、2 → なし、3 → 1個。ラーメン・寿司・海鮮・焼肉・カフェ・居酒屋から i の順に回す |
| 使い道 | `i % 3 == 0` の時だけ「個室あり」 |
| 県・市 | `i % 5`: 富山県 富山市 / 富山県 高岡市 / 石川県 金沢市 / 富山県 富山市 / なし |
| エリア | `i % 5 == 0` の時だけ「総曲輪」「八尾」 |
| 地図 URL | `i % 3 != 2` の時、`https://www.google.com/maps/search/?api=1&query=` ＋ 地名（例「富山市 総曲輪」。場所が無い店は「富山駅」）を URL エンコード |
| メモ | `i % 3`: 4行（長い英数字の URL を含む）／1行「日曜定休。」／なし |

- **i = 0 は全項目あり**、i = 14 は何も無し（タグ・場所・地図・メモとも）。写真の有無は今までどおり（4件に1件は写真なし）
- タグは `findOrCreateTag` で作り、`createShopWithPhotos` の入力にタグ ID を渡す（公開 API だけ）
- **「見本データを消す」**:
  1. 名前が「（見本）」で終わる店を消す（今までどおり）
  2. 残った全店が使っているタグ ID を集める
  3. 見本のタグ（種別と正規化キーが一致するもの）のうち、どの店も使っていないものだけ `deleteTag` で消す
  - `deleteTag` は付いている店からもタグを外すため、手順 2 で使われていないことを確かめてから呼んでいます。花井さんの店が使っているタグ（例「ラーメン」）は残り、その店に付いたまま（単体テストで確認）

## 9. 設計上の判断・迷った点

1. **見出しを付けたのは「場所」と「メモ」だけ**: 仕様の「見出しごと出さない」に合わせ、小さな灰色の見出しを付けました。タグと地図ボタンは見ればわかるので見出し無しです。店名・☆とタグの間は詰め、写真の下の一塊（名前・評価・タグ）として見えるようにしています
2. **見た目の型を本番側に置いた**: `ShopLook` の型と既定値は `src/screens/shopLookTypes.ts`（本番のコード）に置き、`src/dev/` 側は型を import するだけにしました。開発用のコードを本番のコードが静的に import しないためです
3. **バーと浮いた戻るボタンを両方描いて CSS で隠す**: TSX の分岐を無くすためです。隠れている方は `display: none` なので、画面の読み上げやキーボード操作の対象にもなりません
4. **写真なしの帯の色**: `home.css` を触らない条件なので、6色の値を `carousel.css` に複製しました。色を変える時は2か所を直す必要があります（工事4a か工事10でまとめたい）
5. **メモの扱い**: 空白だけのメモはデータ層で「未設定」になりますが、念のため画面側でも空白だけなら出しません。表示するときは保存された文字をそのまま出します（前後の改行も削らない）
6. **見本タグを消す判定**: 見本のタグ名（種別と正規化キー）と一致し、どの店も使っていないタグを消します。花井さんが自分で同じ名前のタグを作って、どの店にも付けずに置いている場合はそれも消えますが、今はタグの入力画面が無い（工事5）ので起きません
7. **画像の遅延読み込みをしていない**: 写真は最大3枚なので、2〜3枚目に `loading="lazy"` を付けていません。横スクロールの中で lazy にすると、払った時に一瞬空白が見えることがあるためです。large は1枚数十〜数百KBで、3枚までなら問題ない見込みです
8. **既存の e2e が変更なしで通った理由**: sessionStorage はテストごとに空なので、既定の「1:1 × バー」で「← 戻る」が出ます。写真1枚の店の代替テキストは店名のままなので、`home.spec.ts` の「大きい写真」の確認もそのまま通ります

### 13-3. 淡色6色のまとめ方と確認結果

**方法**: CSS 変数にしました。
- `tones.css` が `data-tone` の値ごとに `--tone-bg` を決める
- タイル（`.tile-nophoto`）と帯（`.photo-band`）は、どちらも `background: var(--tone-bg, …)` を使うだけ
- 色の値はこのファイルにしか無いので、変える時は1か所で済みます

**理由**
- 色は `data-tone` の番号（`tileToneIndex`）で決まり、タイルと帯で番号の付け方も同じです。だから「番号 → 色」の対応表を1つ置き、使う側は変数を読むだけにするのが素直だと考えました
- 共通のクラスを作って両方の要素に付ける方法もありますが、TSX 側（`ShopTile`）のクラスを変えることになります。CSS 変数なら、TSX の変更は CSS の import 1行だけで済みます
- `tones.css` はタイルと帯の両方の部品から import しています。どちらの画面から開いても色が読み込まれます。本番の CSS に6色の定義は**1回だけ**入ることを確認しました（`dist/` の CSS で `[data-tone=…]` の規則は6個）
- `home.css` の `.tile-nophoto` の規則は、`.tile` の規則より後ろにあります。なので、今までどおり写真なしタイルの背景が勝ちます

**確認結果**（計算後の `background-image` / `background-color`。PC の Chromium、390×844）
- 一覧ページに、写真なしタイルと帯の要素を tone 0〜5 で置いて測りました。変更の前後それぞれで測り、JSON に書き出して `cmp` で比べたところ、**完全に一致**しました
