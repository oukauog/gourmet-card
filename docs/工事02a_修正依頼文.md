### 1. 原因（相談役の見立て）
iPhone は `http://192.168.x.x:5173` で開いています。これは **secure context ではない**ため、`crypto.randomUUID` が存在しません（`crypto.randomUUID is not a function` の TypeError）。`src/lib/id.ts` の `newId()` がこれを直接呼んでおり、`createShop` の最初で例外になって保存全体が失敗していると考えられます。PC の e2e は `localhost`（secure context 扱い）で動くため検出できませんでした。

まず `src/lib/id.ts` を見て、この見立てと矛盾がないか確認してください。矛盾があれば作業を止めて報告してください。

### 2. やること

2-1. **`src/lib/id.ts` の修正**（工事1のファイルですが、今回は相談役が変更を許可します。これ以外の `src/db/`・`src/lib/` の既存ファイルは変更しない）
- `crypto.randomUUID` が使える環境ではそれを使い、無い環境では `crypto.getRandomValues` で UUID v4 を組み立てるフォールバックを入れる（`getRandomValues` は secure context でなくても使える）
- フォールバックは RFC 4122 の v4 形式に正しく従うこと：16 バイトの乱数の 7 バイト目上位 4 ビットを `0100`（version 4）、9 バイト目上位 2 ビットを `10`（variant）にし、`8-4-4-4-12` の小文字 16 進で出す
- フォールバックの関数（例 `uuidV4FromRandomValues()`）は単体テストできるよう export する
- `getRandomValues` も無い環境は想定しない（例外のままでよい）

2-2. **単体テスト** `src/lib/id.test.ts`（新規）
- `uuidV4FromRandomValues()`：正規表現 `^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$` に一致、1000 回生成して重複なし
- `newId()`：`crypto.randomUUID` を一時的に undefined にした状態（`vi.stubGlobal` または `vi.spyOn`。テスト後に必ず復元）でも上の形式の ID を返す
- 既存の `src/db/*.test.ts` は変更しない

2-3. **エラー内容を画面に出す（診断用・仮）** `src/screens/RegisterScreen.tsx`
- 「保存できませんでした。もう一度お試しください」の下に、小さい文字で `例外の name: message` を表示する（例 `TypeError: crypto.randomUUID is not a function`）。iPhone ではコンソールが見えないため、今後の実機確認でも原因が分かるようにするのが目的
- 見た目は最小限。工事3以降で消すか残すかは相談役が決める
