#### 1-1. 自作ハッシュルーター `src/router/`

ライブラリは入れない。画面が少ないアプリなので、次の小さな仕組みで足りる。

**純粋関数**（`src/router/hashRoute.ts`。Node の Vitest で単体テストする。`window` を参照しない）
- `type Route = { screen: 'home' } | { screen: 'register' } | { screen: 'shop'; id: string }`
- `parseHash(hash: string): Route`：`''`・`'#'`・`'#/'` → home、`'#/register'` → register、`'#/shop/<id>'` → shop（id は `decodeURIComponent`）。**それ以外・壊れた形は home** にする（例外を投げない）
- `formatHash(route: Route): string`：`'#/'`・`'#/register'`・`'#/shop/<encodeURIComponent(id)>'`。`parseHash(formatHash(r))` が常に `r` と等しいこと

**ブラウザ側**（`src/router/useHashRoute.ts`）
- `useHashRoute(): Route`：`location.hash` を `parseHash` した値を返し、`hashchange` を購読して更新する。アンマウントで購読解除
- `navigate(route: Route): void`：`location.hash = formatHash(route)`（履歴に**積む**。iPhone の「戻る」スワイプ・ブラウザの戻るで前の画面に戻れる）
- `replaceRoute(route: Route): void`：`history.replaceState` で**積まずに**置き換える（保存後に登録画面へ「戻る」で戻れてしまうのを防ぐ用途）
- 画面の遷移ルール：
  - ホーム →「＋」→ `navigate(register)`
  - 登録の**キャンセル** → `navigate(home)`（`history.back()` は使わない。`#/register` を直接開いて再読み込みした場合に、戻るとアプリの外へ出てしまうため）
  - 登録の**保存後** → `replaceRoute(home)`（登録画面を履歴から消す）＋トースト「保存しました」
  - ホーム → タイルタップ → `navigate(shop, id)`
  - 仮店ページの「戻る」 → `navigate(home)`。削除後 → `replaceRoute(home)`
  - **どの画面でも再読み込みすると同じ画面が出る**こと（`#/register` で再読み込みすれば登録画面、`#/shop/<id>` なら店ページ）
- `App.tsx` は `useHashRoute()` の結果で画面を出し分けるだけにする。DB を開く処理・失敗時の表示・トーストは今のまま維持
